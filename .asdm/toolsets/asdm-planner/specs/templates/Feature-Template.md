## 附录：模板使用说明

### A. 文档命名与存放

**主文档命名格式**：
```
FT-{编号}-{特性名称}-Feature.md
```

**代码分析附件命名格式**：
```
FT-{编号}-{特性名称}-CodeAnalysis.md
```

**存放路径**：
```
docs/planning/Feat/FT-{编号}-{特性名称}/FT-{编号}-{特性名称}-Feature.md
docs/planning/Feat/FT-{编号}-{特性名称}/FT-{编号}-{特性名称}-CodeAnalysis.md
```

**示例**：
```
docs/planning/Feat/FT-003-用户个人令牌/FT-003-用户个人令牌-Feature.md
docs/planning/Feat/FT-049-AgentOrbit数字分身与嵌入式对话/FT-049-AgentOrbit数字分身与嵌入式对话-Feature.md
docs/planning/Feat/FT-049-AgentOrbit数字分身与嵌入式对话/FT-049-AgentOrbit数字分身与嵌入式对话-CodeAnalysis.md
```

### B. 状态标记规范

| 标记 | 含义 | 使用场景 |
|:----:|------|----------|
| ✅ | 已实现 | 功能完整，代码已在主分支或特性分支 |
| ⚠️ | 部分实现 | 功能已编写但存在关键缺失 |
| ❌ | 未实现 | 功能完全不存在 |
| 🔲 | 待实现/待新增 | 计划中的功能，尚未编写代码 |
| ➡️ | 已拆分/已转移 | 功能已拆分到其他特性 |

### C. 优先级标记

| 标记 | 含义 |
|:----:|------|
| P0 | 必须完成，阻塞核心功能 |
| P1 | 应该完成，影响用户体验 |
| P2 | 可以延后，影响安全性或完整性 |
| P3 | 未来考虑，不影响当前版本 |

### D. 风险评估维度

| 维度 | 值 | 含义 |
|------|:--:|------|
| 概率 | 高/中/低 | 风险发生的可能性 |
| 影响 | 高/中/低 | 风险发生后对项目的影响程度 |

### E. 修订记录格式

```markdown
## 修订记录

| 版本 | 日期 | 修订人 | 修订内容 |
|------|------|--------|----------|
| 1.5 | 2026-04-18 | {git user.name} | 新增领域设计；精简文件结构为变更摘要表；目录改为可点击缩进列表 |
| 1.0 | 2026-04-17 | {git user.name} | 初始版本，基于已实现代码生成 |
```

> - 同一天的多次修订必须聚合为一条记录，用分号分隔各项改动内容，版本号取当日最终版本
> - 修订内容应简练：每项改动用短语概括（不超过 10 字），省略具体章节号和细节描述，聚合后整条不超过 60 字
> - 修订人通过 `git config user.name` 检测当前 git 用户名获取

### F. 内容规范（重要）

**特性文档中禁止出现代码示例**：

| 禁止内容 | 替代方案 |
|----------|----------|
| JSON 请求/响应示例 | 使用表格描述字段结构 |
| SQL 建表语句 | 使用表格描述表结构 |
| Java/TypeScript 代码 | 使用文字描述功能和接口 |
| Mermaid 图表 | 使用 ASCII 图表（无需特殊解析器，便于在代码环境中直接阅读） |
| 文件树结构（含具体类文件） | 使用变更摘要表，仅描述模块/包级别的变更范围，不列出具体类文件 |
| 表格格式目录 | 使用可点击的缩进 Markdown 列表格式（见 § 目录） |

**允许使用代码块的情况**：
- ASCII 图表（架构图、ER图、流程图，无需特殊解析器，便于在代码环境中直接阅读）
