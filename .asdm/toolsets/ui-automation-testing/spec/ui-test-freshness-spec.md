# 保鲜工作流规范

## 概述

本规范定义了 `/asdm-ui-test-freshness` action（保鲜指令）的工作流标准。保鲜指令负责检测与新需求相关的自动化测试脚本，并将失效、缺失、过期的脚本恢复可用（方案 v1.1 第 6.3 节）。

## 触发机制

- **v1.0**：定时巡检（人工触发本指令，指定巡检范围）
- **后续版本**：需求变更触发（对接需求管理工具）、代码提交触发（对接代码库 webhook / CI）

## 输入

| 输入 | 来源 | 说明 |
|------|------|------|
| 脚本库 | `.asdm/workspace/ui-test/` 各用例文件夹 | agent-browser 脚本（`.sh`）+ Playwright 降级脚本（`.js`） |
| 录制脚本 | `recordings/<模块>/*.json` | 脚本对应的 Chrome Dev Tools Recorder json |
| 自然语言标注 | 用例文件夹下 `annotations.json` | stepId → 中文描述/预期/来源录制步骤（见 `ui-test-design-generate-spec.md#自然语言标注规范`） |
| 需求描述 | 人工录入 | v1.0 的需求来源，用于覆盖检测与变更更新 |
| 历史执行记录 | 用例文件夹下 `report.md` | 上次执行结果，辅助判断失效脚本 |

## 执行流程

按以下五步依次执行：

### 步骤 1：覆盖检测

比对需求描述涉及的业务环节与现有录制脚本/生成脚本，输出缺失环节清单。

- 列出需求涉及的每个业务环节（页面、操作流程）
- 逐一检查 `recordings/` 是否有覆盖该环节的录制 json
- 输出缺失环节清单：**缺什么环节、应补录哪个录制脚本（目标路径）**
- 存在缺失环节 → 按 `ui-test-manual-fallback-spec.md` 输出补录清单，人工补录归档后重新触发

### 步骤 2：健康检测

对巡检范围内的存量脚本执行巡检运行，收集失败项及报错日志。

- 逐脚本执行（agent-browser `.sh` 优先，缺失时执行 `.js` 降级脚本）
- 无头模式执行：`HEADED=0 bash <脚本>.sh`
- 记录每个脚本：通过 / 失败、失败步骤（从 `[STEP:<id>:START]` 日志定位最后未闭环的 stepId）、报错信息

### 步骤 3：失效修复（AI 自愈）

对步骤 2 中失败的脚本，结合**报错日志 + 对应 recorder json + annotations.json** 进行自愈：

1. 从执行日志定位失败 stepId（最后一个有 `START` 无 `OK` 的步骤）
2. 读取 `annotations.json` 中该 stepId 的自然语言描述与预期结果
3. 读取对应 recorder json 中该步骤的 selectors，结合报错信息判断失效原因：

| 失效原因 | 自愈动作 |
|---------|---------|
| 选择器失效（元素找不到） | 从 recorder json 的多重 selectors 中换用下一优先级选择器；仍失败则用 `agent-browser snapshot` 获取当前页面快照，按步骤描述重新定位 |
| 断言内容变化（文本不匹配） | 比对 recorder json 的期望值与页面实际值，确认是页面变更后更新断言期望值 |
| 页面流程变化（步骤顺序/新增步骤） | 按 annotations.json 的语义描述调整步骤顺序或补插步骤 |
| 环境/数据问题（URL、账号失效） | 更新 `data/` 数据文件，不改脚本 |

4. 每次自愈修改须在脚本对应 `@step` 注释旁追加 `# @healed <日期>: <修改说明>` 记录

### 步骤 4：变更更新

对因需求变更导致**语义过期**的脚本（能跑通但行为已不符合新需求）：

1. 基于人工录入的需求描述，识别受影响的场景与步骤
2. 更新脚本步骤与 `annotations.json` 中的描述
3. **人工确认后入库**：变更内容以 diff 摘要形式提交测试人员确认，确认后生效

### 步骤 5：重跑验证

对自愈/更新后的脚本重跑验证：

- 通过 → 入库（更新用例文件夹中的脚本与标注）
- 不通过 → 计入自愈失败次数，转步骤 3 或转人工（见边界保护）

## 边界保护

- **同一脚本 AI 自愈连续失败达到 2 次**即停止自动尝试，转人工兜底
- 转人工时按 `ui-test-manual-fallback-spec.md` 输出兜底清单：问题脚本、报错原因、AI 已尝试的修复动作
- 禁止在自愈中修改 recorder json 源文件；recorder json 的更新只能来自人工补录
