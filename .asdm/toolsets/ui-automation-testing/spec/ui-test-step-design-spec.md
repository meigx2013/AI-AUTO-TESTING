# 测试步骤设计规范

## 概述

本规范定义了 `/asdm-ui-test-step-design` action 的标准工作流程和产出物格式。测试步骤设计是 "人工录制 + AI 转换" 路线的**前置阶段**——根据 PRD 或一句话需求生成结构化的测试步骤文档和录制计划，驱动人工使用 Chrome DevTools Recorder 精准录制，从而提升后续 `asdm-ui-test-design-generate` 生成的测试脚本的准确性。

### 完整工作流位置

```
需求/PRD
  │
  ▼
[asdm-ui-test-step-design]  ← 本规范
  │  测试步骤设计 + 录制计划
  ▼
人工录制 (Chrome DevTools Recorder)
  │  recordings/<模块>/<模块>-<场景>.json
  ▼
[asdm-ui-test-design-generate]
  │  读取录制 → 检测定位 → 生成双产物脚本
  ▼
[asdm-ui-test-run] → [asdm-ui-test-freshness]
```

## 录制计划规范

### 录制目录结构

所有录制脚本统一存储在项目根目录的 `recordings/` 下，按模块分组：

```
recordings/
├── <模块名>/                          # 按业务模块分组
│   ├── <模块>-<场景1简称>.json        # 场景1的 Chrome DevTools Recorder 录制文件
│   ├── <模块>-<场景2简称>.json        # 场景2的录制文件
│   └── ...
└── .../
```

### 命名规则

| 规则 | 说明 |
|------|------|
| 格式 | `<模块缩写>-<场景简述>.json` |
| 模块缩写 | 全小写英文，如 `schedule`、`login`、`appointment` |
| 场景简述 | kebab-case 英文，如 `add-schedule`、`delete-schedule` |
| 示例 | `schedule-add-schedule.json`、`login-normal.json` |

> **文件名回填说明**：本清单中的录制文件名为**计划名**，仅供人工录制时参考。人工使用 Chrome DevTools Recorder 导出的实际文件名可能因带时间戳、中文或空格而不同（如 `创建顶层组织 2026_7_22 at 13_14_23.json`）。后续 `asdm-ui-test-design-generate` 阶段以 `recordings/` 目录下**真实存在的文件**为准进行匹配，本清单的文件名**不作为**文件名事实来源；请勿在生成阶段强制要求文件名一致。

### 录制脚本与场景的映射表

```markdown
| 录制脚本文件 | 对应场景 | 包含步骤数 | 涉及页面 | 前置条件 |
|-------------|---------|-----------|---------|---------|
| recordings/schedule/schedule-add-schedule.json | SCHEDULE-001 | 8 步 | 诊室页面、排班弹窗 | 医生已登录 |
```

## 二、按产品功能特性拆解的原子操作录制指引

> **本清单面向人工录制，必须自包含、可直接照做**：每个原子操作列出完整录制步骤（操作 / 目标元素 / 预期反馈），**不引用、不省略**。
> 原子操作是"独立可录制"的最小功能单元，按所属**产品功能特性**分组；人工可灵活选择录制顺序与范围（体现灵活性）。
> 内容由 `test-step-design.md` 的场景/步骤设计**派生并重排**而来，二者保持一致即可；本清单允许完整展开步骤（受众不同：本清单供人录制，test-step-design 供 AI 设计）。

## 四、人工补充说明

### 录制技巧

| 技巧 | 说明 |
|------|------|
| 录制前准备 | 确保页面处于前置状态（如已登录）再开始录制 |
| 操作节奏 | 每个操作之间停顿 0.5-1 秒，避免操作过快导致遗漏 |
| 断言添加 | 在关键状态变化点（弹窗出现/数据更新/页面跳转）后添加断言 |
| 录制失败 | 若操作失误，无需停止录制，可继续操作，后续清理错误步骤 |
| 文件保存 | 导出的 JSON 文件名不要包含空格和中文 |

### 常见问题

| 问题 | 解决 |
|------|------|
| 录制时页面跳转后元素变了？ | 正常，Recorder 会自动处理页面状态变化 |
| 录制的选择器不包含 aria-label？ | 可要求开发添加 aria-label 或 data-testid 以增强定位稳定性 |
```

## 录制优先级定义

| 优先级 | 标记 | 含义 | 适用范围 |
|--------|------|------|---------|
| 必须录制 | 🔴 | 必须在录制中包含，否则脚本无法生成 | 所有交互步骤（click/fill/navigate） |
| 建议录制 | 🟡 | 建议录制以增强脚本验证能力 | 断言步骤、验证步骤 |
| 可选录制 | ⚪ | 可不录制，AI 自动处理 | 等待步骤、加载步骤 |

## 测试数据骨架规范

### 数据文件用途

在测试步骤设计阶段生成数据文件骨架，供后续 `asdm-ui-test-design-generate` 使用：

| 文件 | 内容 | 示例 |
|------|------|------|
| `data/env.json` | 环境配置 | baseUrl、targetUrl |
| `data/accounts.json` | 账号数据 | 用户名、密码（敏感信息用 `<需要补充>` 占位） |
| `data/business.json` | 业务数据 | 排班日期、时段、预约数 |

### 骨架文件中的占位规范

| 占位符 | 含义 | 使用场景 |
|--------|------|---------|
| `<需要补充>` | 需要人工补充的值 | 密码等敏感信息、动态配置 |
| `<明天日期>` | 动态日期标记 | 测试步骤设计中的日期字段 |
| `<!-- 注释 -->` | 说明性注释 | 数据文件中对字段含义的补充说明 |

```
├── recordings/                              # 录制文件（唯一脚本来源，项目根目录）

│   ├── feature-list.txt                     # 功能清单输入（人工维护）
│   └── reports/                             # 检测报告（由 check.js --html 生成）
│
└── .asdm/workspace/ui-test/

        ├── test-step-design.md              # 测试步骤设计文档

### 各产出物说明

| 产出物 | 说明 | 下一步用途 |
|--------|------|-----------|
| `test-step-design.md` | 完整的测试步骤设计，含场景拆分、页面分段、步骤描述、元素描述 | 人工录制时的参考文档 |
| `recording-checklist.md` | 可视化的录制清单，含操作指引和断言建议 | 直接驱动人工使用 Chrome DevTools Recorder |
| `data/env.json` | 测试环境配置骨架 | `asdm-ui-test-design-generate` 读取 |
| `data/accounts.json` | 测试账号数据骨架 | `asdm-ui-test-design-generate` 读取 |
| `data/business.json` | 测试业务数据骨架 | `asdm-ui-test-design-generate` 读取 |

## 与 asdm-ui-test-design-generate 的衔接

| 阶段 | 动作 | 产出 | 责任方 |
|------|------|------|--------|
| **阶段 0** | `asdm-ui-test-step-design` | test-step-design.md + recording-checklist.md + data/ | AI |
| **阶段 1** | 人工录制 | recordings/<模块>/<脚本>.json | 测试人员 |
| **阶段 2** | `asdm-ui-test-design-generate` | .sh / .js 脚本 + annotations.json | AI |
| **阶段 3** | `asdm-ui-test-run` | report.md + 人工兜底清单 | AI |

衔接规则：
- `asdm-ui-test-design-generate` 读取 `recordings/` 目录时，**以真实存在的录制文件为准**匹配场景；`recording-checklist.md` 中的计划文件名仅作参考，不强制要求文件名一致（实际导出文件名常带时间戳/中文）
- 如 `test-step-design.md` 已存在，`asdm-ui-test-design-generate` 应直接消费其场景与步骤设计，不再重新推导
- 如录制脚本缺失，`asdm-ui-test-design-generate` 按原流程反馈定位缺失
- `data/` 目录下的骨架文件由 `asdm-ui-test-design-generate` 读取并补充完善（如密码等敏感信息用户需自行补充）
