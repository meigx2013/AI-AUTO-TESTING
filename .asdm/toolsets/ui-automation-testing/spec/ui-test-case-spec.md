## 场景编号规范

- 格式：`<模块缩写>-<序号>`，如 `LOGIN-001`、`CART-003`
- 序号从 001 开始，按功能逻辑排序

## 优先级定义

| 优先级 | 定义 | 示例 |
|--------|------|------|
| P0 | 核心业务路径，必须 100% 通过 | 用户登录、下单支付 |
| P1 | 重要功能，应通过率 ≥ 98% | 个人信息修改、订单查询 |
| P2 | 辅助功能/边界条件，应通过率 ≥ 95% | 空数据展示、特殊字符输入 |

## 选择器最佳实践

1. **优先级顺序**：`data-testid` > `aria-label/role` > `文本内容` > `CSS选择器` > `XPath`
2. **命名规范**：`data-testid` 使用 kebab-case（如 `data-testid="login-submit-btn"`）
3. **避免脆弱选择器**：不要使用自动生成的类名（如 CSS Modules 的 hash 类名）
4. **语义化**：选择器应能表达元素的业务含义
