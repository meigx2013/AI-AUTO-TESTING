# 脚本执行与报告规范

## 概述

本规范定义了 `/asdm-ui-test-run` action 的执行流程标准和执行报告（`report.md`）模板。执行时基于用例文件夹下的 `overview.md` 获取执行计划，按顺序运行各场景脚本，并将结果记录到 `report.md`。

## 执行流程规范

### 执行输入

执行指令接受一个用例文件夹路径作为输入，路径为 `.asdm/workspace/ui-test/<用例名称抽象>_<YYYYMMDDHHmmss>/`。

支持以下输入形式：
- 完整文件夹名：`用户登录功能测试_20260716143022`
- 用例名称抽象前缀匹配：`用户登录功能测试`（匹配最新时间戳的文件夹）

### 执行步骤

1. **locate_folder**：定位目标用例文件夹（如果提供部分名称，按前缀匹配最新的时间戳文件夹）
2. **read_overview**：读取 `overview.md`，提取执行计划章节（`## 四、执行计划`）
3. **parse_plan**：解析执行顺序表和变量传递说明表
4. **clean_data**：执行前删除已有的 `data.json`（如果有），确保每次执行的数据干净；不删除 `data/` 目录下的静态测试数据文件
5. **execute_scripts**：按执行计划的序号顺序依次执行各脚本
6. **generate_report**：将执行结果写入 `report.md`

### 脚本执行规则

按执行计划的 `序号` 列顺序依次执行：

1. 对每一行，检查 `是否可执行` 列：
   - `✅`：执行该脚本
   - `❌`：跳过该脚本，在报告中标记为"未执行"
2. 检查 `依赖场景` 列：
   - `—`：无依赖，直接执行
   - `<场景编号>`：检查依赖场景是否已成功执行；若依赖场景失败或未执行，则跳过当前脚本
3. 选择执行的脚本产物：
   - **agent-browser 脚本（`.sh`）为主产物，优先执行**：`bash "<用例文件夹>/<脚本>.sh"`（无头模式可加 `HEADED=0`）
   - `.sh` 不存在时降级执行 Playwright 脚本：`node "<用例文件夹>/<脚本>.js"`
   - 两者都不存在 → 标记该场景为 ⏭️ 跳过，备注"脚本文件缺失"
4. 记录执行结果：成功/失败、执行耗时、控制台输出
5. 失败处理（v1.0）：脚本失败 → 记录报错原因与上下文日志，转人工兜底（见「转人工清单」章节与 `ui-test-manual-fallback-spec.md`）

### 变量传递

脚本内部通过读取/写入 `data.json` 实现变量传递，本 action 层面只需确保：
- 执行前删除 `data.json`（干净的初始状态）
- 脚本按依赖顺序执行，确保消费变量时 `data.json` 已由前置脚本生成

## 错误处理

| 错误情况 | 处理方式 |
|---------|---------|
| 用例文件夹不存在 | 提示用户文件夹不存在，列出可用的用例文件夹 |
| overview.md 不存在 | 提示该文件夹下缺少 overview.md |
| overview.md 中无执行计划章节 | 提示执行计划缺失，无法确定执行顺序 |
| 执行计划的脚本文件在文件夹中不存在 | 标记该场景为 ❌ 跳过，备注"脚本文件缺失" |
| 依赖场景失败导致当前场景不可执行 | 标记该场景为 ⏭️ 跳过，备注"依赖场景 <编号> 执行失败" |
| node 命令执行失败 | 记录 stderr，标记场景为 ❌ 失败 |
| 脚本执行超时（单脚本 > 5 分钟） | 强制终止，标记为 ❌ 失败，备注"执行超时" |
