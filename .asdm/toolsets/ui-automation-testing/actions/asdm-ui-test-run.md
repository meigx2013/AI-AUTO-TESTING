# Instructions for asdm-ui-test-run action

## Purpose

This instruction guides the AI model to execute test scripts based on the test case folder generated by `/asdm-ui-test-design-generate`. It reads the `overview.md` to get the execution plan, runs scripts in the specified order with dependency handling — **agent-browser scripts (`.sh`, primary) are executed first, Playwright scripts (`.js`) serve as fallback** — and records results into a `report.md`.

**执行时自愈**：当脚本因元素定位失败时，AI 会从脚本中 `# Recorder selectors:` 注释中提取录制原始选择器，尝试替换定位方式并重跑；自愈成功则继续执行，失败达阈值后转人工兜底。（自愈适用范围见 [执行时自愈范围](#自愈范围healing-scope)）

## Language Setting

默认使用**中文（简体中文）**作为输出语言。

## Context Injection

Before executing scripts, the AI model should read the following context:

1. **Run Report Spec** (Required)
   - Path: `.asdm/toolsets/ui-automation-testing/spec/ui-test-run-report-spec.md`
   - Purpose: 遵循执行流程规范和报告模板

2. **Manual Fallback Spec** (Required - on failure after self-healing exhausted)
   - Path: `.asdm/toolsets/ui-automation-testing/spec/ui-test-manual-fallback-spec.md`
   - Purpose: 自愈达到阈值后，按兜底清单模板输出转人工清单

3. **Self-Healing Spec** (Required — for self-healing scope and strategy)
   - Path: `.asdm/toolsets/ui-automation-testing/spec/ui-test-self-healing-spec.md`
   - Purpose: 了解自愈范围（6 类可自愈/5 类不自愈）、自愈流程、选择器替换策略、边界保护规则。执行时自愈和保鲜自愈共用此规范

4. **Agent-Browser Script Spec** (Required — for selector conversion rules)
   - Path: `.asdm/toolsets/ui-automation-testing/spec/ui-test-agent-browser-spec.md`
   - Purpose: 了解 agent-browser 命令格式、选择器转换规则，尤其是 `# Recorder selectors:` 注释格式和「录制 json → agent-browser 命令转换表」，自愈时据此选择合适的 selector 替代方案

5. **Script files under the test case folder** (Required)
   - Path: `.asdm/workspace/ui-test/<用例文件夹>/*.sh`
   - Purpose: 读取脚本中的 `# Recorder selectors:` 注释，获取录制原始选择器列表供自愈使用

6. **用例文件夹下的 overview.md** (Required)
   - Path: `.asdm/workspace/ui-test/<用例文件夹>/overview.md`
   - Purpose: 获取场景列表、执行计划和变量传递说明

7. **固化脚本（优先调用，减少 AI 消耗）** (Recommended)
   - Path: `.asdm/toolsets/ui-automation-testing/scripts/collect-report.js`
   - Purpose: 机械执行数据集下全部脚本并生成 `report.md`（解析运行标记、判定结果、汇总断言覆盖），替代手工逐脚本执行与手工汇总

## Steps to Execute Scripts

### 1. 接收用例文件夹

从用户输入中获取目标用例文件夹：

- **完整文件夹名**：`用户登录功能测试_20260716143022` → 直接定位
- **用例名称前缀**：`用户登录功能测试` → 在 `.asdm/workspace/ui-test/` 下按前缀匹配，选择时间戳最新的文件夹

如果用户未提供，列出 `.asdm/workspace/ui-test/` 下所有可用文件夹让用户选择。

### 2. 定位并验证文件夹

- 检查 `.asdm/workspace/ui-test/<文件夹名>/` 是否存在
- 检查 `overview.md` 是否存在
- 列出文件夹下的所有 `.sh` 与 `.js` 脚本文件

### 3. 读取 overview.md 并解析执行计划

从 `overview.md` 中提取：

**a) 测试场景设计摘要**（`## 一、测试场景设计`）
- 获取每个场景的编号、名称、优先级、脚本文件

**b) 执行计划**（`## 四、执行计划`）
- 解析 `### 执行顺序` 表格，获取：序号、场景编号、场景名称、脚本文件、是否可执行、依赖场景、备注
- 解析 `### 变量传递说明` 表格，获取：变量名、产生场景、消费场景、说明

**解析规范**：执行顺序和变量传递表格格式参见 [ui-test-design-generate-spec.md#执行计划输出格式](../spec/ui-test-design-generate-spec.md#执行计划输出格式)。

### 4. 执行前准备

1. 如果用例文件夹下存在 `data.json`，将其删除（确保干净的执行环境）
2. 确认工作目录为用例文件夹路径

### 5. 按顺序执行脚本

遍历执行计划中的每一行（按 `序号` 列顺序）：

**5a. 可执行性检查**：

| 条件 | 处理 |
|------|------|
| `是否可执行` 为 ❌ | ⏭️ 跳过，备注"脚本不可执行" |
| 脚本文件在文件夹中不存在 | ❌ 标记失败，备注"脚本文件缺失" |
| `依赖场景` 不为 `—`，且依赖场景执行失败或跳过 | ⏭️ 跳过，备注"依赖场景 <编号> 执行失败" |
| 以上全部通过 | 执行脚本 |

**5b. 执行脚本**：

优先执行 agent-browser 主产物脚本，不存在时降级执行 Playwright 脚本：

```bash
# 主产物（优先）
bash "<用例文件夹绝对路径>/<脚本基名>.sh"

# 降级产物（.sh 不存在时）
node "<用例文件夹绝对路径>/<脚本基名>.js"
```

> **注意**：
> - agent-browser 默认无头模式，脚本模板中通过 `HEADED_FLAG="--headed"` 启用有头。执行脚本时 Chrome 窗口会自动弹出。
> - **`--headed` 冲突**：daemon 已运行时传入 `--headed` 会被忽略，且可能干扰 `click` 等命令执行（表现：脚本内点击失败，手动执行同一命令成功）。按以下策略处理：
>   - 第 1 个脚本的 `open` 命令保留 `--headed`（启动浏览器）
>   - 第 1 个脚本的后续命令和第 2~4 个脚本完全移除 `--headed`
> - Windows 环境下 Git Bash 路径（`/c/Users/...`）与 Node.js 不兼容。脚本中已使用 `cygpath -m` 将 Unix 路径转为 Windows 正斜杠路径。若自行执行请确保 Git Bash 可用。
> - Playwright `.js` 降级脚本中的 `page.locator('aria/...')` 或 `page.locator('text/...')` 格式不被 Playwright 原生支持（这是 Chrome Recorder 格式），会报 `Unexpected token "/" in css selector`。此问题不影响 `.sh` 主产物脚本（agent-browser 通过 `find` 命令原生处理）。如确需使用 `.js` 降级，需手动将 `aria/` 换为 `getByPlaceholder()`/`getByRole()`/`getByText()` 等标准 Playwright API。

- 记录执行开始时间
- 捕获 stdout 和 stderr
- 单脚本超时限制：5 分钟（300 秒），超时则强制终止并标记失败
- 记录执行结束时间和耗时

**5c. 判定结果**：
- exit code = 0 → ✅ 成功，继续下一个脚本
- exit code ≠ 0 → ❌ 失败，进入 **[步骤 5d. 执行时自愈](#5d-执行时自愈)**

### 5d. 执行时自愈

脚本执行失败后，AI 模型先按 [ui-test-self-healing-spec.md#自愈范围](../spec/ui-test-self-healing-spec.md#自愈范围healing-scope) 判断是否属于可自愈的失败类型。**仅当匹配时才启动自愈，否则直接转人工兜底。**

自愈流程、选择器替换策略、边界保护规则详见 [ui-test-self-healing-spec.md](../spec/ui-test-self-healing-spec.md)。

### 5e. 重跑验证

自愈修改完成后，重新执行该脚本（重新调起 `bash` 执行整个 `.sh`，而非从失败步骤恢复）：

```bash
bash "<用例文件夹绝对路径>/<脚本基名>.sh"
```

- exit code = 0 → ✅ 自愈成功，记录到自愈记录，继续后续脚本
- exit code ≠ 0 且自愈未达阈值 → 回到 **[步骤 5d](#5d-执行时自愈)** 尝试第 2 次自愈
- exit code ≠ 0 且已达阈值（2 次）→ ❌ 自愈失败，标记失败，转入人工兜底清单

### 5f. 机械执行 + 生成报告（优先调用固化脚本）

**优先调用** `scripts/collect-report.js` 一次性完成"按执行计划运行全部脚本 + 解析标记 + 生成 report.md"的机械工作，**避免 AI 逐脚本手工执行与手工汇总**：

```bash
node .asdm/toolsets/ui-automation-testing/scripts/collect-report.js <用例名或前缀>
```

脚本会（详见其头部注释）：
- 解析 `overview.md` 执行计划（场景设计摘要 / 脚本执行顺序 / 变量传递说明）得到执行顺序
- 自动清理 `data.json`，按顺序运行 `.sh`（缺失时降级 `.js`），单脚本超时 10 分钟
- 解析 `[EXEC:START/END]`、`[STEP:*:START/OK]`、`[LOGIN:*]` 标记与 ❌ 断言失败，判定每个场景成功/失败/跳过（依赖场景失败则跳过后续）
- 生成 `report.md`（六章：总览 / 各场景详情 / 变量传递 / 结论 / 断言覆盖 / 转人工清单）

> **AI 的角色**：collect-report.js 只做机械运行与汇总，**选择器转换与自愈仍需 AI**。脚本执行完成后，AI 读取 `report.md` 中标记为 ❌ 失败的场景，进入 [步骤 5d](#5d-执行时自愈) 判断是否可自愈；自愈修改后重跑该脚本（或重跑 collect-report.js 整体刷新报告），并在报告的"自愈记录"章节补写自愈动作。

### 6. 生成报告（report.md）

若已在 [步骤 5f](#5f-机械执行--生成报告优先调用固化脚本) 调用 `collect-report.js`，则 `report.md` 已机械生成，**本步骤 AI 只需**：
- 在 `report.md` 中补充"自愈记录"章节（记录 [步骤 5d](#5d-执行时自愈) 中实际发生的自愈：场景、失败类型、替换前后选择器、是否成功）
- 对转人工清单中的失败场景，按 [ui-test-manual-fallback-spec.md#兜底清单模板](../spec/ui-test-manual-fallback-spec.md#兜底清单模板) 补全"AI 已尝试的修复动作"与"建议人工操作"

未使用 collect-report.js 时，按 [ui-test-run-report-spec.md#报告模板](../spec/ui-test-run-report-spec.md#报告模板) 从零生成 `report.md`，写入用例文件夹下：

```
.asdm/workspace/ui-test/<用例文件夹>/report.md
```

报告包含七个章节：

1. **执行总览**：场景总数、成功/失败/跳过数、总耗时、通过率
2. **自愈记录**（新增）：自愈触发的场景、失败类型、替换前后的选择器、自愈是否成功
3. **各场景执行详情**：每个场景的脚本文件（主/降级产物）、状态、耗时、控制台输出、错误信息
4. **变量传递记录**：变量名、产生场景、值摘要、消费场景、传递状态
5. **执行结论**：通过/部分通过/未通过 判定 + 失败场景总结
6. **断言覆盖情况**：断言步骤数/操作步骤数、各场景断言明细
7. **转人工清单**：失败脚本按 [ui-test-manual-fallback-spec.md#兜底清单模板](../spec/ui-test-manual-fallback-spec.md#兜底清单模板) 输出（自愈失败达阈值后转人工；无失败则标注"无"）

## Execution Guidelines

### When to Use This Action

Use this action when:
- 用户已通过 `/asdm-ui-test-design-generate` 生成了测试用例脚本
- 需要执行某个用例文件夹下的所有场景脚本
- 需要生成执行报告

### Dependency Handling

- 严格按执行计划的序号顺序执行
- 依赖场景失败 → 后续依赖它的场景全部跳过
- 变量传递由各脚本内部通过 `data.json` 自行处理，本 action 只负责确保执行前 `data.json` 已清除

### Error Handling

按 [ui-test-run-report-spec.md#错误处理](../spec/ui-test-run-report-spec.md#错误处理) 处理各类错误情况：

| 错误情况 | 处理方式 |
|---------|---------|
| 用例文件夹不存在 | 提示并列出可用文件夹 |
| overview.md 缺失 | 提示并终止 |
| 执行计划章节缺失 | 提示无法确定执行顺序 |
| 脚本文件缺失 | 标记该场景跳过 |
| 依赖场景失败 | 跳过当前场景，备注原因 |
| 执行超时 | 强制终止，标记失败，不自愈 |
| 非定位类异常（网络/语法/agent-browser 未安装等） | 不自愈，直接转人工清单 |
| 元素定位失败（自愈范围内） | 按 [ui-test-self-healing-spec.md](../spec/ui-test-self-healing-spec.md) 进入自愈流程，最多 2 次 |
| 自愈达 2 次阈值 | 标记失败，转入人工清单 |

## Usage

To use this instruction, the AI model should:

1. 接收用例文件夹名称（完整或前缀）
2. 定位 `.asdm/workspace/ui-test/<文件夹>/`
3. 读取 `overview.md` 解析执行计划（参见 [执行计划输出格式](../spec/ui-test-design-generate-spec.md#执行计划输出格式)）
4. 清理 `data.json`（如有；不删除 `data/` 目录下的静态测试数据文件）
5. 按执行顺序依次运行各脚本：**优先调用 `scripts/collect-report.js <用例名>` 机械批量执行并生成 `report.md`**（见 [步骤 5f](#5f-机械执行--生成报告优先调用固化脚本)）；或逐脚本 `bash` 执行 agent-browser `.sh`（主产物），缺失时降级 `node` 执行 `.js`
6. 收集每个脚本的执行结果（状态、耗时、输出、断言通过情况）
7. 脚本失败时，判断是否属于 [自愈范围](../spec/ui-test-self-healing-spec.md#自愈范围healing-scope)：
   - ✅ 是 → 从 `# Recorder selectors:` 注释获取备选选择器，按 [自愈流程](../spec/ui-test-self-healing-spec.md#自愈流程) 修复并重跑（最多 2 次）
   - ❌ 否 → 直接记入转人工清单
8. 按 [报告模板](../spec/ui-test-run-report-spec.md#报告模板) 生成 `report.md`（含自愈记录、断言覆盖情况与转人工清单）

## 固化脚本（优先调用，减少 AI 消耗）

本 action 的机械部分（按执行计划批量运行脚本 + 解析运行标记 + 汇总报告）已由 `scripts/collect-report.js` 实现，**执行时应优先调用脚本，AI 仅处理需语义判断的部分**（选择器转换、执行时自愈、自愈记录撰写）：

- `scripts/collect-report.js`：按 `overview.md` 执行计划机械运行全部 `.sh`（降级 `.js`），解析 `[EXEC:START/END]`/`[STEP:*:START/OK]`/`[LOGIN:*]` 标记与 ❌ 断言失败，生成六章 `report.md`。
  - 调用：`node scripts/collect-report.js <用例名或前缀>`
  - AI 仅对报告中 ❌ 失败场景做自愈判断与修复，并在报告补写"自愈记录"章节。
