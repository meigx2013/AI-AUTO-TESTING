# test-plan：生成测试计划（测试任务 + 全量编排脚本）

> **执行本文档即生成测试计划与全量编排脚本**：大模型按 §四 步骤扫描
> `.asdm/workspace/replay-testcase/` 下的回放脚本（**数量不限，记为 N**）与
> `test-cases/` 用例源文件，结合 `spec/directory-structure-spec.md`（下称 spec）
> 的目录与落盘约定，生成两份可直接使用的静态文件：
>
> - `task/test-plan.md`：测试计划（测试任务定义，静态快照）
> - `task/run-all.sh`：全量执行编排脚本（静态快照）
>
> - 术语约定：本工具集中**测试计划 = 测试任务定义**——要执行哪些任务、按什么
>   顺序、用什么登录身份与数据、怎样判定通过；一条任务 = 一个回放用例脚本
> - **通用性：本文档为抽象命令文件，不绑定任何具体测试案例**。任务数量 N、
>   任务清单、依赖链、豁免/阻塞判定全部从目录扫描与脚本内容动态得出；
>   新增 / 删除 / 重命名脚本后重新执行本文档即可生成与当前脚本集合一致的计划
> - 输入：`.asdm/workspace/replay-testcase/`（`replay_testcase/<编号>_<用例名>.sh`
>   + `common/common.sh` + `data/test-data.sh`）+ `test-cases/*.md` + README 依赖树
> - 输出：`task/test-plan.md` + `task/run-all.sh`（模板见 §五；`task/` 不存在时
>   先 `mkdir -p` 创建）
> - 定位：本文件（`.asdm/toolsets/transfer/generate-test-plan.md`）是**生成逻辑
>   唯一来源**；`task/` 下两个文件是生成产出的静态快照，不含生成逻辑，需要新
>   计划时重新执行本文件，禁止在实例文件内手写生成规则
> - 下游：`execute-test-task.md` 按计划逐任务执行；`run-all.sh` 是计划中
>   「全量执行」方式的编排落地（spec §2.3）
> - 自给自足：本文档内联全部扫描规则、生成规则与目标文件模板，不依赖外部文件

## 前置条件

- 回放脚本就位：`.asdm/workspace/replay-testcase/replay_testcase/` 下存在一个或多个
  `<编号>_<用例名>.sh`（数量不限，记为 N），公共库 `common/common.sh` 就位
  （历史布局为根目录下 `replay_testcase_<编号>_<用例名>.sh` + 同级 `common.sh`，
  按 §2.1 判定后写入实际路径）
- `data/test-data.sh` 存在（提供批次 `TEST_TS`、变量清单与凭据）
- 用例源文件 `test-cases/<编号>_<用例名>.md` 存在（提供用例语义与依赖链参照）
- 仅需文件读取，不要求被测平台可达（可达性在执行阶段由 execute-test-task 校验）

## 二、输入扫描清单（生成依据）

### 2.1 目录布局判定

| 判定 | 特征 | 计划中「执行入口」列写法 |
| --- | --- | --- |
| 定版布局（spec 合规，现役） | 脚本位于 `replay_testcase/`，公共库位于 `common/common.sh` | `replay_testcase/<编号>_<用例名>.sh`（相对 `replay-testcase/` 根） |
| 历史布局 | 脚本平铺于 `replay-testcase/` 根目录、文件名带 `replay_testcase_` 前缀 | `replay_testcase_<编号>_<用例名>.sh`（相对 `replay-testcase/`） |

历史布局时计划照常生成，头部「布局」字段标注 `历史（未迁移）` 并附一句迁移提示；
执行入口按实际路径书写，保证计划可直接执行。

### 2.2 脚本清单与逐脚本信息提取（任务四要素）

**脚本清单**：对 `.asdm/workspace/replay-testcase/replay_testcase/` 执行
glob 匹配 `<编号>_<用例名>.sh`（现役布局；历史布局为根目录下
`replay_testcase_*.sh`），得到 N 个脚本；脚本 slug = 文件名去掉目录与后缀的
`<编号>_<用例名>` 部分（如 `replay_testcase/001_system-login.sh` → `001_system-login`）。

对每个脚本提取以下信息，**全部以脚本实际内容为准**，禁止凭用例 md 臆造：

| 要素 | 提取位置 | 示例（`<编号>_<用例名>` 泛化） |
| --- | --- | --- |
| 前置依赖 | 头部注释「前置条件」节中"先执行 replay_testcase/XXX"字样 | 依赖其他脚本 slug |
| 必需数据 | `require_vars …` 行的变量名列表 | ASDM_USER ASDM_PASS PAT_NAME |
| 落盘产出 | 头部「注：…写入 $DATA_DIR/…」注释 + `save_element_value` 调用 | `data/pat.txt` |
| 登录身份 | 脚本消费的凭据变量（见 §3.3 映射表） | super-admin / test01 |

补充规则：

- 跨文件数据消费（如 `PAT="${PAT:-$(cat "${DATA_DIR}/pat.txt" …)}"`）
  同时计入「数据依赖」列（`data/pat.txt`）与「前置」列（依赖产出该文件的脚本）
- 脚本头部前置条件与 README 依赖树**冲突时以脚本为准**（脚本反映实际实现），
  并在生成报告（§四 step 8）中标注差异

### 2.3 其他输入

| 输入 | 提取内容 | 用途 |
| --- | --- | --- |
| `data/test-data.sh` | 头部「最近刷新」的 `TEST_TS`；各变量默认值（含空值与占位符特征，见 §3.4） | 批次信息列 + 豁免/阻塞判定 |
| `test-cases/*.md` | 用例名、操作概要（一句话） | 任务表「说明」列 |
| `README.md` §用例总览/执行顺序 | 依赖树 | 依赖链校验参照（§3.2） |
| spec §2.3/§2.4 | `task/`、`result/` 职责与日志命名 | 执行方式与日志路径约定 |
| `data/` 目录现状 | 跨脚本落盘数据文件（如 `pat.txt`）是否存在且非空 | 消费方数据就绪判定 |

## 三、生成规则

### 3.1 任务清单（一脚本一任务）

- 任务行 = 脚本扫描四要素（§2.2）+ 用例一句话说明（§2.3），逐字段填入 §五 A 模板任务表
- 任务数 N = 扫描到的脚本数（§2.2 glob 结果），**与具体用例无关，N 可为任意正整数**
- 任务顺序按编号升序排列（如 001→012→…）；执行顺序由依赖链单独表达（§3.2），
  不混排在同一张表
- 编号相同（重号脚本，如历史遗留与现役用例同号）时：按用例名升序，并在生成
  报告中标注冲突与处理（以 slug 全名区分任务，slug 唯一即可）
- 每行「状态」字段按 §3.4 判定：就绪 / 豁免 / 阻塞

### 3.2 依赖链（动态构建，替代固定骨架）

**不再预设固定骨架**，依赖链完全由脚本内容推导：

1. 对每个脚本，从头部注释「前置条件」节提取所有
   `replay_testcase/<编号>_<用例名>` 引用（去重、排除自身）→ 得到依赖边
2. 汇总全部依赖边构成有向图（DAG）；无前置声明的脚本依赖链根节点（如登录类）
3. 执行顺序 = 依赖拓扑序；同层（无依赖关系的平行任务）按编号升序；
   spec §2.3 约定「编号序即依赖序」，生成器据此校验：若依赖指向更大编号
   （逆序依赖）则以依赖为准重排，并在计划头部「差异备注」中标注
4. 收尾类脚本（头部注释含「收尾」/「退出登录」等清除登录态语义）默认按编号
   参与拓扑排序；若其依赖仅"存在登录态"（依赖根节点），生成器可将执行序置尾
   并在报告中标注

校验规则：N 个任务全部出现在链上（无孤立任务）；依赖无环；无悬空依赖
（被依赖的脚本不存在）；任一校验失败 → 终止生成并报告差异。

### 3.3 登录身份

身份由脚本消费的凭据变量动态判定，内置映射表（可按环境扩展）：

| 凭据变量 | 身份 |
| --- | --- |
| `ASDM_USER` / `ASDM_PASS` | super-admin |
| `TEST01_USER` / `TEST01_PASS` | test01 |

- 匹配规则：脚本 `require_vars` 中出现 `TEST01_*` → test01；否则消费 `ASDM_*`
  或无显式凭据 → super-admin
- 身份切换由执行方以环境变量覆盖传入（单脚本单登录身份约定，testcase-to-sh §7.2）；
  若脚本本身内置身份切换（脚本内 `ASDM_USER=TEST01_USER` 赋值），生成器在
  计划任务表「身份」列备注"脚本内置切换，调用方无需传环境变量"，
  `run-all.sh` 相应无需额外处理

### 3.4 数据就绪判定（豁免/阻塞）

**通用判定规则**（对每个任务逐一判定，不针对特定变量）：

| 判定条件 | 状态 | 处理 |
| --- | --- | --- |
| 该任务 `require_vars` 的所有变量在 `test-data.sh` 有非空默认值 | 就绪 | 正常入表 |
| 某必需变量默认值为**空**或为**占位符**（默认值含占位符特征，如 `xxx`、`…`、`placeholder` 等；具体特征由生成器扫描 test-data.sh 时确定并写入 run-all.sh 的 `PLACEHOLDER`） | 豁免-缺外部数据 | 任务保留，状态标注，不阻塞后续任务；生成对应 `EXEMPT_RULES` 条目（§五 B），执行时变量仍为空/占位符则跳过 |
| 跨脚本落盘数据缺失（如消费方脚本读取 `data/pat.txt` 而文件缺失或为空） | 阻塞-缺前置产出 | 标注"先执行产出该数据的脚本"；若依赖链内前置先行则按序自然解决 |
| `TEST_TS` 批次对应数据已在平台执行过（创建类重名） | 提示 | 头部备注"回放前执行 generate-test-data.md 刷新批次" |

占位符特征约定：test-data.sh 中某变量默认值含 `xxx` / `…`（全角省略号）/
`placeholder` 等明显非真实值特征，或值为空，即视为占位符。生成器在报告中列出
所有豁免任务及依据（变量、默认值、解除方式）。

### 3.5 执行方式

| 方式 | 命令（项目根目录） | 适用 |
| --- | --- | --- |
| 全量 | `bash .asdm/workspace/replay-testcase/task/run-all.sh` | 一轮完整验收（与本计划同批生成，见 §五 B；单任务失败不中断，继续执行剩余任务） |
| 单任务 | `bash .asdm/workspace/replay-testcase/<执行入口>` | 调试 / 补跑（需身份覆盖的任务按 §3.3 传环境变量） |
| 断点续跑 | 从失败任务起按依赖序逐个单任务执行 | run-all 中断后；禁止整批重跑（创建类用例不幂等） |

日志统一落 `result/`，命名 `<编号>_<用例名>-<YYYYMMDD_HHMMSS>.log`（spec §2.5；
现役实现为固定名覆盖式 `<编号>_<用例名>.log`，见 §五 B 与 test-plan.md §七 差异 14）；
整轮执行另落 `result/run-all.log` 综合日志。

### 3.6 通过标准

- 任务级：脚本退出码 0（`finish` 汇总 WARN=0）且日志中无 `[失败]` / `[断言失败]`
- 计划级：全部 N 个任务「通过」或「豁免」且有留痕（§五 A 模板第六节），无未处理的「阻塞」

## 四、执行步骤（AI 操作步骤）

**step 1：判定目录布局**（§2.1）——确认脚本实际位置，决定「执行入口」列写法
与头部「布局」字段。

**step 2：扫描脚本清单并逐脚本提取任务四要素**（§2.2）——在
`replay_testcase/` 下 glob 匹配 `<编号>_<用例名>.sh` 得到 N 个脚本，读取各脚本头部注释与
`require_vars` / `save_element_value` 调用行，汇总为任务草表。

**step 3：读取数据与就绪状态**（§3.4）——从 `data/test-data.sh` 取 `TEST_TS`
与变量默认值（含空值/占位符特征），检查跨脚本落盘数据文件现状，为每个任务标注
就绪/豁免/阻塞。

**step 4：构建并校验依赖链**（§3.2）——从脚本前置注释提取依赖边构 DAG，
拓扑排序得执行顺序；确认 N 任务齐、无环、无悬空依赖；冲突以脚本为准并记录差异。

**step 5：生成计划文件**——`mkdir -p .asdm/workspace/replay-testcase/task`，
按 §五 A 模板写入 `task/test-plan.md`，头部记录生成时间、TEST_TS、布局、N、差异备注。

**step 6：生成编排脚本**——按 §五 B 模板写入 `task/run-all.sh`：
`TASKS` 数组 = step 4 的拓扑执行顺序（slug 列表）；`EXEMPT_RULES` = step 3 判定的
豁免任务及其对应变量；`PLACEHOLDER` = step 3 确定的占位符特征；布局相关注释按
step 1 结论写入。

**step 7：验证**——任务行数 = 脚本数 N；任务表「执行入口」路径全部实际存在
（`test -f` 逐条核验）；`bash -n task/run-all.sh` 语法校验通过；身份、依赖、产出
与脚本注释一致；豁免/阻塞项均有留痕字段。

**step 8：报告**——向用户报告：任务总数 N、就绪/豁免/阻塞分布、TEST_TS 批次、
发现的脚本与 README 依赖差异、重号等冲突处理、建议执行入口
（全量 / 单任务 / 断点续跑命令）。

```bash
# ============================================================================
# 【生成说明】本文件由 .asdm/toolsets/transfer/generate-test-plan.md 生成
#   （静态快照），禁止手写编辑；任务清单/豁免判定/占位符特征由生成器按
#   目录扫描结果写入下方「生成器写入区」。脚本集合变化后重新执行生成文档。

#   历史（根目录平铺 replay_testcase_<编号>_<用例名>.sh）> 布局，
#   执行入口按实际布局定位（迁移后需重新生成以更新路径）。
# 【身份切换】<生成器按 §3.3 判定写入，如："部分脚本内置身份切换，调用方
#   无需传环境变量；如需覆盖 TEST01_USER=... TEST01_PASS=... bash 本脚本">
# 【豁免判定】EXEMPT_RULES 中任务对应变量为空或占位符 → 豁免跳过
#   （test-plan §3.4；以环境变量传入真实值即可解除，环境变量优先于 test-data.sh）
# 【日志】每任务落盘 result/<编号>_<用例名>.log（现役实现为固定名覆盖式，
#   spec §2.5），控制台同步 tee 输出；整轮输出另落 result/run-all.log。
# 【失败策略】单任务失败不中断：继续执行剩余任务直至全部完成，每个任务的
#   通过/豁免/失败结果均计入汇总表与综合日志（失败任务的下游依赖任务可能
#   连锁失败，属预期留痕）；补跑用断点续跑：从失败任务起单任务执行，
#   禁止整批重跑（创建类用例不幂等，见 test-plan §四）。
# ============================================================================
# 【运行环境守卫】本脚本依赖 bash 专属特性（>(...) 进程替换、数组、${!var}），
#   被 sh（POSIX 模式 bash）/ dash / zsh 调用会报语法错误，此处自动转 bash 重执行：
if [ -z "${BASH_VERSION:-}" ] || { command -v shopt >/dev/null 2>&1 && shopt -qo posix; }; then
    exec bash "$0" "$@"
fi

set -uo pipefail

ROOT_DIR="$(cd "$(dirname "$0")/.." && pwd)"     # replay-testcase/
DATA_DIR="${ROOT_DIR}/data"
RESULT_DIR="${ROOT_DIR}/result"
mkdir -p "$RESULT_DIR"

# 加载统一测试数据（环境变量优先），用于豁免条件判定
if [ -f "${DATA_DIR}/test-data.sh" ]; then
    # shellcheck disable=SC1091
    . "${DATA_DIR}/test-data.sh"
fi

# ==================== 生成器写入区（勿手改） ====================
# 任务清单：依赖拓扑执行顺序（<N> 个，见 test-plan §三）
TASKS=(
    <task-slug-1>
    <task-slug-2>
    <…>
)

# 豁免规则：task|VAR —— VAR 为空或占位符时该任务豁免跳过（test-plan §3.4）
EXEMPT_RULES=(
    <task-slug>|<VAR>
    <…>
)

# 占位符特征：test-data.sh 中豁免变量默认值含此特征 → 视为占位符（生成器写入）
PLACEHOLDER='<占位符特征，如 xxx>'
# ==================== 生成器写入区结束 ====================

RUN_TS="$(date +%Y%m%d_%H%M%S)"
RUN_LOG="${RESULT_DIR}/run-all-${RUN_TS}.log"   # 综合日志（整轮输出 + 汇总）

# 全部输出（逐任务日志、结果汇总、最终统计）同步 tee 落盘综合日志
exec > >(tee "$RUN_LOG") 2>&1

PASS=0; EXEMPT=0; FAIL=0
declare -a RESULTS=()   # "任务|结果|日志"

echo "============================================================"
echo " ASDM 回放全量执行  开始: $(date '+%Y-%m-%d %H:%M:%S')"
echo " 根目录: ${ROOT_DIR}"
echo " 任务数: ${#TASKS[@]}"
echo " 数据批次 TEST_TS: ${TEST_TS:-未知（test-data.sh 未声明）}"
echo " 综合日志: ${RUN_LOG}"
echo "============================================================"

for tc in "${TASKS[@]}"; do
    script="${ROOT_DIR}/replay_testcase/${tc}.sh"
    if [ ! -f "$script" ]; then
        echo "[run-all] [失败] 脚本不存在: ${script}，继续执行后续任务" >&2
        RESULTS+=("${tc}|失败|脚本不存在")
        FAIL=$((FAIL+1))
        continue
    fi

    # ---------- 豁免判定（EXEMPT_RULES：变量为空或占位符 → 跳过） ----------
    skip_reason=""
    for rule in "${EXEMPT_RULES[@]}"; do
        t="${rule%%|*}"; var="${rule#*|}"
        [ "$t" = "$tc" ] || continue
        val="${!var:-}"
        case "$val" in
            ""|*"${PLACEHOLDER}"*)
                skip_reason="变量 ${var} 未设置或为占位符（test-plan §3.4）"; break;;
        esac
    done
    if [ -n "$skip_reason" ]; then
        echo "[run-all] ------ 任务 ${tc} 豁免：${skip_reason} ------"
        RESULTS+=("${tc}|豁免|${skip_reason}")
        EXEMPT=$((EXEMPT+1))
        continue
    fi

    # ---------- 执行 + 日志落盘 ----------
    log="${RESULT_DIR}/${tc}.log"          # 固定名覆盖式（断点续跑依据 [结果] 通过）
    echo "[run-all] ------ 执行任务 ${tc}（日志: ${log}）------"
    if bash "$script" 2>&1 | tee "$log"; then
        echo "[run-all] 任务 ${tc} 通过"
        RESULTS+=("${tc}|通过|${log}")
        PASS=$((PASS+1))
    else
        echo "[run-all] [失败] 任务 ${tc} 未通过，继续执行剩余任务（下游依赖任务可能连锁失败；补跑用断点续跑，见 test-plan §四）" >&2
        RESULTS+=("${tc}|失败|${log}")
        FAIL=$((FAIL+1))
        continue
    fi
done

echo "============================================================"
echo " 执行汇总  结束: $(date '+%Y-%m-%d %H:%M:%S')"
echo " ----------------------------------------------------------"
printf " %-42s %-4s %s\n" "任务" "结果" "日志/原因"
for r in "${RESULTS[@]}"; do
    task="${r%%|*}"; rest="${r#*|}"
    status="${rest%%|*}"; detail="${rest#*|}"
    printf " %-42s %-4s %s\n" "$task" "$status" "$detail"
done
echo " ----------------------------------------------------------"
echo " 通过 ${PASS} / 豁免 ${EXEMPT} / 失败 ${FAIL}（共 ${#TASKS[@]} 个任务）"
echo " 综合日志: ${RUN_LOG}"
echo "============================================================"

[ "$FAIL" -eq 0 ] && exit 0 || exit 1
```

## 六、重新生成时机

- **脚本集合变化后**：新增 / 删除 / 重命名回放脚本（N 变化）——`test-plan.md`
  与 `run-all.sh` **必须同步重新生成**，保持任务清单与豁免判定一致
- **刷新数据批次后**：`generate-test-data.md` 产出新 `TEST_TS`，计划头部与
  就绪/豁免判定需同步
- **目录布局迁移后**：历史布局 → 定版布局（`replay_testcase/` + `common/`），执行入口路径全变
- **脚本头部变更后**：前置条件、`require_vars`、落盘产出注释有增删
- **test-data.sh 变量变化后**：豁免变量增删、占位符特征变化
- 同一批执行中断后**不**重新生成（保持断点续跑上下文与豁免记录）

## 已知限制

- 计划只描述"任务与执行方式"，不校验平台可达性、`agent-browser` 可用性等
  运行时前置（属 `execute-test-task.md` 职责）
- 依赖链以脚本注释为准确，脚本注释缺失时退化用 README 依赖树兜底，
  兜底决策须写入计划头部「差异备注」
- 依赖拓扑序依赖脚本头部注释的规范性；注释缺失且无 README 兜底时退化为
  编号升序并标注
- 豁免判定基于 `test-data.sh` 静态默认值；执行时以环境变量补齐数据的话，
  计划中的豁免状态不会自动更新，需重新生成或人工改状态
- 重号脚本（编号相同、slug 不同）按用例名排序，任务表以 slug 区分；
  若同号脚本语义冲突（如同名不同义）需人工裁决
- 旧布局下生成的计划可执行，但不符合 spec §一 结构；迁移后必须重新生成
  （执行入口路径不同），旧计划与旧编排脚本随迁移作废弃
