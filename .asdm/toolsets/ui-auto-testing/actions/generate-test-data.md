# generate-test-data：按批次号生成 test-data.sh 测试数据（变量总登记表 + 赋值规则体系 + 全量刷新）

> **执行本文档即生成一批测试数据**：大模型按 §四 步骤操作，以显式批次号（如 `T001`）
> 按 §一 变量总登记表"赋值规则"列与 §二 赋值规则体系，对 test-data.sh 定义域
> **全部变量（59 个）**逐一求值（**变量级规则优先 → 无规则按批次生成规则兜底**），
> 整体重写 `.asdm/workspace/replay-testcase/data/test-data.sh`，
> 供 003→004→005→010→011 依赖链（含 024/025/026 挂链创建类）及独立创建类
> 用例整批回放使用。
>
> - 输入：**批次号（必传）**，如 `T001`（位置参数；可选 `BATCH_ID` 环境变量等价）；
>   缺失或非法（不匹配 `^T[0-9]{3,4}$`）即终止并提示用法
> - 输出：刷新 `.asdm/workspace/replay-testcase/data/test-data.sh`——
>   头部记录 `BATCH_ID`；**全部定义域变量整体重写**：名称类空规则 → 批次实例
>   （`T001_类别词序号`）、`fixed` 规则按字面值重算（结果与当前值相同即幂等）、
>   `ref` 规则按依赖拓扑序字面复制、`env` 凭据原样保留；刷新前自动备份
>   `data/.backup/test-data.<批次号>.<日期>.sh`
> - 定位：本文件是 **① 全部用例变量的唯一登记处**（§一 变量总登记表，
>   `/testcase-to-sh` 新增变量必须先在此登记（含初始值/赋值规则两列），
>   再按登记结果向 `test-data.sh` 追加实例分节），
>   **② 生成逻辑唯一来源（登记表"赋值规则"列）**；`test-data.sh` 是**静态实例**
>   （数据快照），禁止在文件内写运行时生成逻辑
> - 规则语法基线：`docs/03_variable-rule-t1-baseline.md`（T1 定版：五类语法、
>   求值顺序、冲突处理、环检测终止条件）
> - 自给自足：本文档内联全部规则与目标文件模板（§五），不依赖外部文件

## 一、变量总登记表（全部用例变量唯一登记处）

登记表是**全部用例变量**的唯一登记入口：`/testcase-to-sh` 转换用例时识别出的新变量，
必须**先在本表登记**（变量名 / 类别 / 实例序号 / 取值属性 / 初始值 / 赋值规则 /
依赖对齐 / 来源用例），再按登记结果向 `test-data.sh` 追加实例分节；
未登记变量禁止出现在 `test-data.sh`。

### 1.0 登记字段与维护铁律

每条登记记录字段（共 10 字段；**"初始值""赋值规则"为变量规则改造新增**）：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 变量名 | bash 变量名 | `SUB_ORG_NAME` |
| 类别 | 命名类别（决定类别词，见 §二） | 组织名称 |
| 实例序号 | 创建型变量占号（两位，同类别内唯一，先登记先占号）；引用型填 `=引用目标` | `02` / `=组织01` |
| 取值属性 | 批次实例 / 引用 / 固定值 / 外部凭据(豁免) / 运行产物——**登记时的初始归类；与赋值规则冲突时以规则为准**（铁律 5） | 批次实例 |
| 固定值 | 取值属性为固定值/凭据时填写（名称类分表省略此列，恒为不适用）——**降级为 `fixed` 规则的冗余校验字段** | `admin@2026` |
| **初始值** | **用例输入的字面值（用例 md 原文抄录）**；无法回溯的历史变量（006~026/099 用例不在本仓、公共配置）填 `（缺）`并在备注写兜底来源。**纯回溯锚点（档案字段），不参与求值** | `测试组织01` |
| **赋值规则** | **变量级规则表达式（§2.0 五类语法）**；留空 = 未单独定义，按批次生成规则兜底（§2.1~§2.4）。**求值唯一依据** | `ref:ORG_NAME` |
| 依赖对齐 | 引用型变量的字面对齐目标（目标必须在登记表内）——**降级为 `ref` 规则的冗余校验字段**：ref 目标 ≠ 依赖对齐目标 → 登记表校验告警 | `=ORG_NAME` |
| 来源用例 | 首次引入该变量的用例编号 | 004 |
| 备注 | 平台约束、豁免条件、定义未引用、脚本级标注、差异决断、规则-属性冲突差异等 | 平台令牌名唯一性校验 409 |

**维护铁律**：

1. **登记表 ⊇ test-data.sh 定义变量集**：表外变量禁止出现在 `test-data.sh`；
   "test-data.sh 定义变量集 ⊆ 登记表且登记表内 test-data.sh 定义域与文件定义集 diff 为空"
   是每次生成 / 转换的必过验证（命令见 §四 step 4）
2. 分表结构：名称类 9 张（§1.1–§1.9，空规则按 §二 类别词批次化）+ 场景智能体资源引用
   1 张（§1.10，`fixed` 规则字面锚定，不批次化、不占序号）+ 非名称类 1 张（§1.11，
   `fixed` / `env` / `ref` 规则），共 11 张
3. 现行登记规模：**67 条 = test-data.sh 定义 59 + 脚本级 8**。"脚本级"指回放脚本内
   经环境变量可覆盖、`test-data.sh` 未定义的变量，登记表备注必须标注"脚本级"
4. 引用型变量（实例序号 `=引用目标` / 依赖对齐非空）的字面值在生成时必须等于
   其对齐目标变量的实例值（字面对齐，禁止 bash 变量引用）；该约束的形式化载体即
   登记表"赋值规则"列的 `ref:<目标>` 规则
5. **赋值规则优先于取值属性**：两列矛盾时以赋值规则为准，"取值属性"降级为登记时的
   初始归类，差异写入备注（典型案例：`PIPELINE_NAME` 取值属性历史登记"固定值"→
   规则列 `batch` 生效）
6. **初始值为回溯锚点，不参与求值**：求值唯一依据是"赋值规则"列——固定值类一律写
   显式 `fixed:<字面值>`（或敏感值形态 `fixed:（现值）`，见 §2.0），不依赖初始值列
   求值；初始值 ≠ 当前值属正常差异（如 `BASE_URL` sit→dt01 环境迁移），记备注
7. **人工改动必须回填登记表**：对 `test-data.sh` 的人工修改（值/规则/新增变量）必须
   先回填登记表对应列再执行刷新，否则整体重写会覆盖该改动（生成逻辑单源铁律）

## 二、赋值规则体系（变量级规则 + 批次生成兜底）

### 2.0 变量级赋值规则（求值唯一依据，T1 定版）

**五类规则语法**：

| 规则写法 | 求值语义 | 典型变量 |
| --- | --- | --- |
| （空，缺省） | 批次生成规则兜底（§2.1~§2.4）：名称类 → `批次号_类别词+序号`；**非名称类 → 取初始值**（保持用例输入值不动，供转换期冷启动后未派规则的新变量沿用） | `ORG_NAME`、`TEST01_USER` |
| `batch` | 显式批次实例（与空规则名称类等价）；用于非名称类别需强制批次化、或语义变更点显式化的场景 | `PIPELINE_NAME` |
| `fixed[:字面值]` | 固定值；省略字面值时取"初始值"字段（仅当初始值=期望值时的等价简写）。**存量固定值一律写显式 `fixed:<当前值>`**，使求值不依赖初始值列；**敏感值形态 `fixed:（现值）`** = 取 test-data.sh 中该变量现行字面值原样写回（凭据明文不入本文档，敏感纪律） | `TEST01_PASS`→`fixed:admin@2026` |
| `ref:<目标变量>` | 字面对齐：值 = 目标变量**本轮求值结果**的字面复制（禁止 bash 变量引用铁律不变）；目标必须在登记表内且属 test-data.sh 定义域，求值按依赖 DAG 拓扑序 | `PARENT_ORG`→`ref:ORG_NAME` |
| `env:<占位特征>` | 外部凭据/环境注入：**不参与批次重算**——非占位态（文件已有真实值）刷新时**原样保留**；占位态（值为空或含 `xxx` 特征）**保持占位值不动**；未入文件时写占位特征派生的占位值（如 `ghp_`→`ghp_xxx`、空占位→空值）。豁免判定沿用 run-all（值为空或含 `xxx` 特征 → 豁免-缺外部数据） | `GH_TOKEN`→`env:ghp_` |

> `expr` 模板表达式（`{BATCH}`/`{SEQ}` 占位符拼接）暂不引入——现行 67 条变量全部可由上述 5 类覆盖；确有需求时后续扩展，语法版本在文档头部标注。

**初始值与规则的职责分离**：初始值承载用例原文（档案、回溯锚点），规则承载生成语义
（求值唯一依据），两者互不推导；用例改版时对照"初始值 → 当前值"快速定位需同步的变量。

**求值顺序**（`/generate-test-data <批次号>` 对定义域 59 条逐一求值）：

1. **Pass 1（无依赖，任意序）**：空规则 / `batch` / `fixed` / `env` 全部求值；
2. **环检测前置**：对登记表全部 `ref` 边构建有向图（节点=定义域变量），Kahn 拓扑排序——
   反复消解入度为 0 的节点，**排序结束后剩余节点数 > 0 ⇔ 存在环**；命中环 → **立即终止
   刷新**（不写入 test-data.sh），输出环上变量清单与涉及的 `ref` 边清单及修复指引
   （"去除环上任一条 ref 边或改为 fixed/batch"）；
3. **Pass 2（依赖序）**：`ref` 变量按拓扑序逐个字面复制目标**本轮求值结果**（保证链式
   传递一致，如 005→004→003）。

**`ref` 目标校验**（求值前置）：目标不在登记表内 → 终止报告"未登记目标"；目标属脚本级
（8 条之一，不在定义域）→ 终止报告"ref 目标不可为脚本级变量"；目标规则为 `env` →
允许（复制其保留值字面），备注提示语义慎用。

**冲突处理**：赋值规则与"取值属性"矛盾时**以赋值规则为准**，"取值属性"降级为登记时
初始归类，差异写入备注（§1.0 铁律 5）；"依赖对齐"列与 `ref` 目标不一致、"固定值"列与
`fixed:字面值` 不一致 → 登记表校验告警（冗余校验字段，§1.0 铁律）。

**脚本级条目（8 条）不入 test-data.sh、不参与刷新**：规则列仅语义标注
（`fixed`=脚本内默认 / `env`=外部注入与运行产物）。

### 批次生成规则（未单独定义规则的变量兜底）

> 本章为登记表"赋值规则"列**留空（或 `batch`）**变量的兜底求值规则；变量级规则
> （§2.0）优先于本章。

#### 2.1 批次号

- 格式：`T` + 3 位十进制数字（如 `T001`、`T002`）；容量不足时可扩展为 4 位
  （`T1000` 起），规则同构
- 校验：`^T[0-9]{3,4}$`，不合法即终止（§四 step 1）
- 批次号是唯一批次标识，贯穿 `test-data.sh` / `test-plan.md` / `run-all.sh`
- 批次推进纪律见 §六（每轮 +1、同批禁生成、断点续跑不生成、重名失败换下一批次号）

#### 2.2 命名模板与类别词

**通用命名模板**：`<批次号>_<类别词><序号>`。序号两位数字、从 `01` 起、
同一类别内按登记表登记顺序自动递增（先登记先占号，§一 各分表的"实例序号"列）。

需求命名示例（逐字）：`T001_USER01@asdm.ai`、`T001_组织01`、`T001_组织02`、
`T001_组织03`、`T001_PAT01`、`T001_PAT02`、`T001_项目01`、`T001_项目02`、
`T001_知识空间01`、`T001_知识空间02`。当前登记表实际占用序号：USER01、组织01/02、
PAT01、项目01、知识空间01/02、智能体空间01/02、知识源01/02、分身01/02、流水线01；
`组织03`、`PAT02`、`项目02` 等待后续新增实例登记时按序号自然出现。

类别词与实例分配映射（定版，与 §一 登记表一致）：

#### 2.3 规则细则

1. **创建型变量占序号**：每个在平台执行"创建"动作的名称变量占用该类别的一个序号；
   序号按登记表登记顺序分配（先登记先占号）
2. **引用型变量不占序号**：`PARENT_ORG`、`NEW_USER_ORG`、`ORG_NODE`、`ASDM_ORG_NAME`
   等下游引用变量字面等于其指向的上游实例值（字面对齐原则不变，禁止变量引用）；
   该约束由登记表规则列 `ref:<目标>` 承载（§2.0）；文件名派生类引用（场景智能体
   资源名 = `UPLOAD_FILE` 文件名）不占序号、不批次化，以 `fixed:<文件名字面值>` 锚定
3. **同一实例多个消费变量共享值**：如 `NEW_USER_EMAIL = TEST01_USER = T001_USER01@asdm.ai`，
   由登记表 `ref:` 规则与"依赖对齐"字段显式声明
4. **固定值/凭据/外部占位符不参与批次兜底**：由登记表规则列显式承载
   （`fixed:<字面值>` / `fixed:（现值）` / `env:<占位特征>`），"取值属性"列仅为登记时
   初始归类（规则优先，§1.0 铁律 5）
5. **批次推进规则**：每轮完整回放前批次号 +1（T001 → T002），防创建类重名；
   **同一批回放内禁止再次生成数据**（依赖链断裂，原约束保留）；断点续跑 /
   回放历史批次不重新生成、沿用原批次号
6. **防撞名兜底**：若指定批次号的数据已在平台执行过（重名失败），改用下一批次号
   重新生成——批次号可人肉指定，天然规避旧时间戳秒级精度的并发撞名限制

  （012/024/025 选项文案差异均已实测核对并记 test-plan §七，仅平台选项变更时人工更新
  并回填登记表）——规则列 `fixed:<字面值>`

## 三、依赖链对齐规则（处理流程正确性）

同一 `BATCH_ID` 必须贯穿整条依赖链，下游变量值必须与上游产物**字面一致**
（写入静态值，不用变量引用）。该约束的形式化载体是登记表"赋值规则"列的
`ref:<目标>` 规则——**本节对齐表与登记表规则列一一对应（冗余校验）**：

| 下游变量 | 必须等于 | T001 批次实例值 | 上游用例产物 |
| --- | --- | --- | --- |
| `PARENT_ORG` | `ORG_NAME` 的值 | `T001_组织01` | 003 创建的顶层组织 |
| `NEW_USER_ORG` | `SUB_ORG_NAME` 的值 | `T001_组织02` | 004 创建的子组织 |
| `NEW_USER_EMAIL` | `TEST01_USER` 的值 | `T001_USER01@asdm.ai` | 005 创建的用户（010/011 登录账号） |
| `NEW_USER_PASS` | `TEST01_PASS` 的值 | `admin@2026`（固定值） | 同上 |
| `ORG_NODE` | `SUB_ORG_NAME` 的值 | `T001_组织02` | 010 项目所在组织节点 |
| `PROJECT_NAME` | 批次实例（旧"子组织名 + `-项目`"规则废止） | `T001_项目01` | 010 项目名（8 字符 ≤ 20 上限） |

依赖链：`003 创建顶层组织 → 004 创建子组织 → 005 创建用户 → 010 创建项目 → 011 项目设置`
（024 在线智能体空间 / 025 在线知识空间 / 026 多步构建挂靠 010 项目，见下"挂链创建类"）。
任何一环批次实例不一致，后续用例都会因找不到上游数据（组织不存在 / 用户不存在 /
登录失败）而失败。

## 四、执行步骤（生成数据）

**step 1：解析并校验批次号参数**

- 优先取位置参数（用法：`/generate-test-data T001`）；未给参数时取 `BATCH_ID`
  环境变量（二者等价）
- 校验格式：`echo "$BATCH" | grep -Eq '^T[0-9]{3,4}$'`
- **缺失或非法即终止**，提示用法：`用法：/generate-test-data <批次号>（如 T001）`

**step 2：按登记表"赋值规则"列求值全部定义域变量（59 个）**

变量级规则优先、留空（或 `batch`）按 §二批次生成规则兜底（§2.0 求值顺序）：

1. **Pass 1**：空规则 / `batch` / `fixed` / `env` 全部求值；
2. **环检测**：对 §一 登记表全部 `ref` 边做 Kahn 拓扑检测，有环即终止并输出环上
   变量清单（§2.0）；
3. **Pass 2**：`ref` 变量按拓扑序字面复制目标本轮求值结果。

以 `BATCH_ID=T001` 为例（名称类/引用型求值结果；序号分配依据 §一 登记表，
先登记先占号）：

## 六、批次推进与刷新时机

- **每轮完整回放前：批次号 +1 并重新生成**（T001 → T002 → …）：上一批已在平台留下
  同名组织/用户/项目/空间/知识空间/知识源/分身/流水线配置（含在线空间与多步知识源）
  时，不换批次号重跑会因重名失败（组织已存在 / 邮箱已注册 / 名称重复 / 令牌 409）
- **同一批回放内禁止再次生成**：003 已按旧实例创建组织后再生成，004 起引用的就是
  平台上不存在的新数据，依赖链断裂
- **断点续跑 / 回放历史批次**：不重新生成，保持文件中既有批次实例，沿用原批次号
- **防撞名兜底**：指定批次号的数据已在平台执行过（重名失败）时，改用下一批次号
  重新生成
- **批次号对账**：`test-data.sh` 头部【数据批次】记录最近批次号，人为推进批次号前
  必须与之核对（防跳号/复用导致平台数据错乱）
- **人工改动回填**：`test-data.sh` 的人工修改必须先回填登记表（§1.0 铁律 7），
  否则下次整体重写会覆盖该改动

## 已知限制

- 每批回放都会在平台上留下 `T0xx_` 前缀的 用户/组织/项目/空间/知识空间/知识源/
  分身/流水线配置（不自动清理），需按前缀定期辨识与批量清理
- 类别序号上限 99（两位）：同一类别超 99 个实例时报错提示扩展类别
  （现行每类别实例数 ≤2，余量充足）
- 批次号人为管理（无自动递增机制）：跳号/复用会导致平台数据错乱，以 `test-data.sh`
  头部最近批次号对账（§六）
- 邮箱本地部分 `T001_USER01` 的合法性（大写字母/下划线）需实跑核对平台注册约束；
  不合规则在登记表单点改类别词（如降级为全小写），规则结构不变
- 修改命名规则（类别词/序号/批次号格式）或赋值规则语法须同步更新本文件
  §一/§二/§三/§五 与 `docs/03_variable-rule-t1-baseline.md`（语法基线）
- `data/test-data.sh` 含明文凭据，禁止提交版本库（`chmod 600`，同 directory-structure-spec）；
  凭据明文同样不入本文档（`fixed:（现值）` / `env` 规则形态承载）
