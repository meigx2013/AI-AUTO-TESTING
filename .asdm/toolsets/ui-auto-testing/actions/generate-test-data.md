# generate-test-data：按批次号生成 test-data.sh 测试数据（变量总登记表 + 批次生成规则）

> **执行本文档即生成一批测试数据**：大模型按 §四 步骤操作，以显式批次号（如 `T001`）
> 按 §二 命名规则与 §一 变量总登记表，将全部名称类变量的批次实例
> （用户 / 组织 / 项目 / PAT / 知识空间 / 智能体空间 / 知识源 / 数字分身 / 流水线配置，
> 及 020/021 现存组织引用等引用型变量）写入 `data/test-data.sh`，
> 供 003→004→005→010→011 依赖链（含 024/025/026 挂链创建类）及独立创建类
> 用例整批回放使用。
>
> - 输入：**批次号（必传）**，如 `T001`（位置参数；可选 `BATCH_ID` 环境变量等价）；
>   缺失或非法（不匹配 `^T[0-9]{3,4}$`）即终止并提示用法
> - 输出：刷新 `.asdm/workspace/replay-testcase/data/test-data.sh`——
>   头部记录 `BATCH_ID`，全部名称类变量值改为批次实例（`T001_类别词序号`）；
>   固定值 / 外部凭据 / 运行产物保持原值不动
> - 定位：本文件是 **① 全部用例变量的唯一登记处**（§一 变量总登记表，
>   `/testcase-to-sh` 新增变量必须先在此登记，再向 `test-data.sh` 追加实例），
>   **② 生成逻辑唯一来源**；`test-data.sh` 是**静态实例**（数据快照），
>   禁止在文件内写运行时生成逻辑
> - 自给自足：本文档内联全部规则与目标文件模板（§五），不依赖外部文件

## 前置条件

- 目标文件存在：`.asdm/workspace/replay-testcase/data/test-data.sh`（不存在时按 §五模板新建）
- 仅需 `bash`（验证用）；不依赖被测平台可达

## 一、变量总登记表（全部用例变量唯一登记处）

登记表是**全部用例变量**的唯一登记入口：`/testcase-to-sh` 转换用例时识别出的新变量，
必须**先在本表登记**（变量名 / 类别 / 实例序号 / 取值属性 / 依赖对齐 / 来源用例），
再按登记结果向 `test-data.sh` 追加实例分节；未登记变量禁止出现在 `test-data.sh`。

### 1.0 登记字段与维护铁律

每条登记记录字段：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 变量名 | bash 变量名 | `SUB_ORG_NAME` |
| 类别 | 命名类别（决定类别词，见 §二） | 组织名称 |
| 实例序号 | 创建型变量占号（两位，同类别内唯一，先登记先占号）；引用型填 `=引用目标` | `02` / `=组织01` |
| 取值属性 | 批次实例 / 引用 / 固定值 / 外部凭据(豁免) / 运行产物 | 批次实例 |
| 固定值 | 取值属性为固定值/凭据时填写（名称类分表省略此列，恒为不适用） | `admin@2026` |
| 依赖对齐 | 引用型变量的字面对齐目标（目标必须在登记表内） | `=ORG_NAME` |
| 来源用例 | 首次引入该变量的用例编号 | 004 |
| 备注 | 平台约束、豁免条件、定义未引用、脚本级标注等 | 平台令牌名唯一性校验 409 |

**维护铁律**：

1. **登记表 ⊇ test-data.sh 定义变量集**：表外变量禁止出现在 `test-data.sh`；
   "test-data.sh 定义变量集 ⊆ 登记表且登记表内 test-data.sh 定义域与文件定义集 diff 为空"
   是每次生成 / 转换的必过验证（命令见 §四 step 4）
2. 分表结构：名称类 9 张（§1.1–§1.9，按 §二 类别词批次化）+ 场景智能体资源引用
   1 张（§1.10，引用型不批次化、不占序号）+ 非名称类 1 张（§1.11，固定值 /
   外部凭据 / 运行产物），共 11 张
3. 现行登记规模：**67 条 = test-data.sh 定义 59 + 脚本级 8**。"脚本级"指回放脚本内
   经环境变量可覆盖、`test-data.sh` 未定义的变量，登记表备注必须标注"脚本级"
4. 引用型变量（实例序号 `=引用目标` / 依赖对齐非空）的字面值在生成时必须等于
   其对齐目标变量的实例值（字面对齐，禁止 bash 变量引用）

## 二、批次号命名规则（创建规则）

### 2.1 批次号

- 格式：`T` + 3 位十进制数字（如 `T001`、`T002`）；容量不足时可扩展为 4 位
  （`T1000` 起），规则同构
- 校验：`^T[0-9]{3,4}$`，不合法即终止（§四 step 1）
- 批次号是唯一批次标识，贯穿 `test-data.sh` / `test-plan.md` / `run-all.sh`
- 批次推进纪律见 §六（每轮 +1、同批禁生成、断点续跑不生成、重名失败换下一批次号）

### 2.2 命名模板与类别词

**通用命名模板**：`<批次号>_<类别词><序号>`。序号两位数字、从 `01` 起、
同一类别内按登记表登记顺序自动递增（先登记先占号，§一 各分表的"实例序号"列）。

需求命名示例（逐字）：`T001_USER01@asdm.ai`、`T001_组织01`、`T001_组织02`、
`T001_组织03`、`T001_PAT01`、`T001_PAT02`、`T001_项目01`、`T001_项目02`、
`T001_知识空间01`、`T001_知识空间02`。当前登记表实际占用序号：USER01、组织01/02、
PAT01、项目01、知识空间01/02、智能体空间01/02、知识源01/02、分身01/02、流水线01；
`组织03`、`PAT02`、`项目02` 等待后续新增实例登记时按序号自然出现。

类别词与实例分配映射（定版，与 §一 登记表一致）：

| 类别 | 类别词 | 实例格式 | 现行实例分配（登记表序号） |
| --- | --- | --- | --- |
| 用户邮箱 | `USER` | `T001_USER01@asdm.ai` | `TEST01_USER`/`NEW_USER_EMAIL` → USER01（同一实例，005 创建、010/011 登录复用） |
| 组织名称 | `组织` | `T001_组织01` | `ORG_NAME` → 组织01；`SUB_ORG_NAME` → 组织02；`PARENT_ORG`/`ASDM_ORG_NAME`/`ORG_CONFIG_NAME`/`NEW_USER_ORG`/`ORG_NODE` 为引用型（见 §1.2） |

### 2.3 规则细则

1. **创建型变量占序号**：每个在平台执行"创建"动作的名称变量占用该类别的一个序号；
   序号按登记表登记顺序分配（先登记先占号）
2. **引用型变量不占序号**：`PARENT_ORG`、`NEW_USER_ORG`、`ORG_NODE`、`ASDM_ORG_NAME`
   等下游引用变量字面等于其指向的上游实例值（字面对齐原则不变，禁止变量引用）；
   文件名派生类引用（场景智能体资源名 = `UPLOAD_FILE` 文件名）同样不占序号、不批次化
3. **同一实例多个消费变量共享值**：如 `NEW_USER_EMAIL = TEST01_USER = T001_USER01@asdm.ai`，
   由登记表"依赖对齐"字段显式声明
4. **固定值/凭据/外部占位符不参与命名规则**：`*_PASS`、`*_ROLE`、`FLAG_STATUS`、
   `GH_TOKEN`（占位符豁免）等保持静态值，登记表以"取值属性"区分
5. **批次推进规则**：每轮完整回放前批次号 +1（T001 → T002），防创建类重名；
   **同一批回放内禁止再次生成数据**（依赖链断裂，原约束保留）；断点续跑 /
   回放历史批次不重新生成、沿用原批次号
6. **防撞名兜底**：若指定批次号的数据已在平台执行过（重名失败），改用下一批次号
   重新生成——批次号可人肉指定，天然规避旧时间戳秒级精度的并发撞名限制

### 2.4 固定数据不走创建规则（保持静态值）

以下数据不参与批次命名，全量清单与当前值见 §1.11（固定值 / 外部凭据 / 运行产物）：

  共用，留空则 run-all.sh 豁免，不参与批次化）、`GH_TOKEN`（占位符豁免）、
  `PROJECT_ADMIN_USER`/`PROJECT_ADMIN_PASS`（空值豁免）
- 固定选项/文本类：`*_TYPE`、`*_DESC`、`*_BUILD_MODE`、`FLAG_STATUS`、`RUN_PROMPT` 等
  （012/024/025 选项文案差异均已实测核对并记 test-plan §七，仅平台选项变更时人工更新）
- 【语义变更】`PIPELINE_NAME` 已从固定值清单移出（原固定值 `pipeline`），

- **每轮完整回放前：批次号 +1 并重新生成**（T001 → T002 → …）：上一批已在平台留下
  同名组织/用户/项目/空间/知识空间/知识源/分身/流水线配置（含在线空间与多步知识源）
  时，不换批次号重跑会因重名失败（组织已存在 / 邮箱已注册 / 名称重复 / 令牌 409）
- **同一批回放内禁止再次生成**：003 已按旧实例创建组织后再生成，004 起引用的就是
  平台上不存在的新数据，依赖链断裂
- **断点续跑 / 回放历史批次**：不重新生成，保持文件中既有批次实例，沿用原批次号
- **防撞名兜底**：指定批次号的数据已在平台执行过（重名失败）时，改用下一批次号
  重新生成
- **批次号对账**：`test-data.sh` 头部【数据批次】记录最近批次号，人为推进批次号前
  必须与之核对（防跳号/复用导致平台数据错乱）

## 已知限制

- 每批回放都会在平台上留下 `T0xx_` 前缀的 用户/组织/项目/空间/知识空间/知识源/
  分身/流水线配置（不自动清理），需按前缀定期辨识与批量清理
- 类别序号上限 99（两位）：同一类别超 99 个实例时报错提示扩展类别
  （现行每类别实例数 ≤2，余量充足）
- 批次号人为管理（无自动递增机制）：跳号/复用会导致平台数据错乱，以 `test-data.sh`
  头部最近批次号对账（§六）
- 邮箱本地部分 `T001_USER01` 的合法性（大写字母/下划线）需实跑核对平台注册约束；
  不合规则在登记表单点改类别词（如降级为全小写），规则结构不变
- 修改命名规则（类别词/序号/批次号格式）须同步更新本文件 §一/§二/§三/§五
- `data/test-data.sh` 含明文凭据，禁止提交版本库（`chmod 600`，同 directory-structure-spec）
