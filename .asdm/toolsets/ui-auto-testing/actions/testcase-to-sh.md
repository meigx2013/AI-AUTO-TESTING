# testcase-to-sh：测试用例 markdown → agent-browser 回放脚本（通用转换规范）

> 将测试用例 markdown（操作步骤 / 预期结果 / 前置条件 三段式）翻译为可直接执行的
> bash 回放脚本，驱动 agent-browser 完成端到端 UI 自动化。本文档是**通用转换
> 规范**：只定义"步骤模式 → 翻译模板"的映射规则与公共机制，不绑定任何
> 具体用例内容，任意 ASDM（及同类 Web 平台）测试用例均按此转换。
>
> - 输入：**单个用例文件**（`NNN_名称.md`）或**整个用例目录**（批量转换，§十）
> - 输出（输出根目录固定 `.asdm/workspace/replay-testcase/`，相对项目根）：
>   - 每个用例一个回放脚本 `replay_testcase/<NNN>_<名称>.sh`（脚本子目录，无前缀）
>   - 首次转换时生成公共库 `common/common.sh`（全部脚本 source 复用，§二）
>   - 首次转换时生成统一数据文件 `data/test-data.sh`（§五）
>   - 全量转换时生成编排 `task/run-all.sh` 与 `task/test-plan.md`（§九）
> - 配套文档：`spec/agent-browser-spec.md`（CLI 能力）、
>   `spec/directory-structure-spec.md`（目录语义）、`generate-test-data.md`
>   （批次数据刷新）、`test-plan.md`（测试计划生成）

## 前置条件

- 安装 `agent-browser` CLI（`snapshot` / `click` / `fill` / `select` / `upload` /
  `wait` / `get` / `press` / `eval` / `reload` / `open` 子命令可用；拿不准 ref
  约定时执行 `agent-browser skills get core --full` 核对当前版本用法）
- 被测平台可达（地址以 `data/test-data.sh` 的 `BASE_URL` 为准；用例 md 中的
  URL 仅作参考，与环境不一致时以 test-data.sh 统一，差异记入交付说明）
- 用例"前置条件"一节所列依赖已满足（§六；脚本不做自动级联，登录类前置除外）

## 一、产出物与目录布局

```
.asdm/workspace/replay-testcase/
├── common/                                    # 公共方法库目录
│   └── common.sh                              # §二，一次生成、全部脚本复用
├── replay_testcase/                           # 回放脚本目录（每用例一个，NNN 序=依赖序）
│   └── <NNN>_<名称>.sh                        # 如 001_system-login.sh
├── data/
│   ├── test-data.sh                           # 统一测试数据（§五，generate-test-data.md 刷新）
│   └── <跨用例中间数据文件>                    # 如令牌/ID 等落盘产物（§4.7）
├── task/
│   ├── run-all.sh                             # 全量回归编排器（§九）
│   └── test-plan.md                           # 测试计划静态实例
└── result/                                    # 每任务日志 + 综合日志（执行时创建）
    └── <NNN>_<名称>-<YYYYMMDD_HHMMSS>.log
```

- **当前定版为 `common/` + `replay_testcase/` 双目录布局**（脚本与公共库分目录同级，
  脚本文件名不再带 `replay_testcase_` 前缀——目录名已表达归属）。`spec/directory-structure-spec.md`
  的 `sh/<NNN_名称>/` 案例子目录是更远期的目标态；若迁移，须同步调整脚本内
  `SCRIPT_DIR` 相对定位与 `task/run-all.sh` 执行入口，并重新生成 test-plan
- 路径换算：脚本位于 `replay_testcase/`，故 `${SCRIPT_DIR}/../common/common.sh`
  = 公共库、`${SCRIPT_DIR}/../data` = 数据目录
- 设计原则：**业务脚本只写"做什么"，common.sh 负责"怎么驱动浏览器"**——
  修复与增强单点沉淀、全脚本共享；禁止在业务脚本内复制库函数

## 二、公共库 common/common.sh

### 2.1 回放脚本骨架模板（每个用例按此生成）

```bash
#!/bin/bash
# 由 <NNN_名称>.md 翻译而来（测试用例 markdown → agent-browser）
#
# 通用操作已抽取至 common.sh（快照 ref 驱动），本脚本仅保留用例业务步骤：
#   <一句话业务链路概括>
#
# 前置条件（不自动级联，缺失即报错）：
#   1. <按用例"前置条件"一节逐条翻译，依赖前置用例的注明"先执行 replay_testcase/XXX_YYY.sh">
#
# 运行（工作目录 = replay-testcase/）：bash replay_testcase/<NNN>_<名称>.sh（默认显示浏览器窗口）
# 如需无头模式：HEADED=0 bash replay_testcase/<NNN>_<名称>.sh

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"      # = .../replay-testcase/replay_testcase
# shellcheck disable=SC1091
. "${SCRIPT_DIR}/../common/common.sh"            # 公共库在同级 common/ 目录

# 统一测试数据：data/test-data.sh（含全部用例数据，环境变量优先）
DATA_DIR="${SCRIPT_DIR}/../data"                 # 数据在同级 data/ 目录
load_data_file "${DATA_DIR}/test-data.sh"

BASE_URL="${BASE_URL:-<平台默认地址>}"

ab_init
require_vars <仅列本用例实际用到的变量，按 §5.1 命名约定>

# ---------- 操作步骤 ----------
# step N(原步骤号): <动作描述>        ← 逐条翻译，见 §四
# ---------- 预期结果断言 ----------
# 预期结果 N: <断言描述>              ← 见 §七
# ---------- 收尾 ----------
finish
```

### 2.2 方法族速查（common.sh 提供的能力）

| 族 | 函数 | 用途 |
|---|---|---|
| 初始化 | `ab_init` / `load_data_file` / `require_vars` | 建目录、加载数据、校验必需变量（缺失 exit 1） |
| 快照定位 | `snap_i` / `extract_ref` / `ref_by_text` / `ref_by_label` / `ref_by_exact` / `snapshot_line_after` / `refs_of_role` | 快照取 ref（子串 / 标签 / 精确 / 行后角色 / 角色枚举） |
| 等待轮询 | `ab_wait` / `wait_for_ref_by_text` / `wait_for_ref_by_label` / `wait_for_url_match` / `wait_for_url_gone` / `wait_for_text` | SPA 渲染/跳转/异步结果全部轮询，禁一次性断言 |
| 元素操作 | `ab_click`（核心）/ `click_by_text` / `click_by_exact` / `fill_by_label` / `fill_by_any_label` / `click_radio` | 点击与填充（JS 优先、禁用轮询、soft 模式，§2.3） |
| 下拉框 | `select_option` / `select_by_native` | 两步法展开点击；浮层不可点时原生 `select` 兜底 |
| 上传/取值 | `upload_file` / `get_element_value` / `save_element_value` | 隐藏 input 探测注入；元素值抓取与落盘（600 权限） |
| 树/搜索 | `expand_all_tree` / `click_tree_node` / `search_and_filter` / `clear_search_box` / `cell_after` | 树展开与精确点击；列表搜索过滤；行内取列 |
| iframe | `act_in_frame` | BFS 穿透同源多层 iframe 按 CSS/XPath 定位操作 |
| 断言 | `assert_snapshot_contains` / `assert_snapshot_missing` / `assert_visible` / `assert_url_matches` / `assert_url_not_matches` / `assert_file_not_empty` | 软断言累加 WARN；硬断言立即 exit 1（§七） |
| 登录导航 | `is_logged_in` / `login` / `click_user_info` / `goto_admin_console` / `goto_platform_settings` / `click_tab` / `goto_org_project` / `click_confirm_if_present` | 平台级流程复用（§4.2） |
| 收尾 | `finish` | WARN>0 → exit 1（CI 判定出口），每脚本必调 |

common.sh 已存在时**直接复用不重生成**；转换中发现的通用新能力（多处复用的
定位/操作/断言模式）先沉淀进 common.sh 再在脚本中调用，禁止在业务脚本内
内联通用函数。

### 2.3 关键设计决策（翻译时必须遵循）

1. **快照 ref 铁律**：ref 仅对当次快照有效，任何改变页面结构的操作后必须
   重新取快照。库函数内部自行取快照定位，调用方不跨步持有 ref
2. **点击走 `ab_click`，JS 优先、快照 ref 兜底**：agent-browser 坐标点击对
   部分 SPA 链接/侧边栏元素会静默失效，JS `el.click()` 可靠；JS 内文本经
   base64 传递（无注入风险）；命中 `disabled`/`notfound` 时轮询等待控件
   启用（受控组件重渲染有延迟，属时序性问题），上限 8 次
3. **soft 模式**：`ab_click ... soft` 未命中仅告警返回 1 不退出——用于
   "可能出现也可能不出现"的弹窗确认链（幂等场景）
4. **精确匹配优先**：目标文本是其他元素文本的前缀、或列表/树中存在同名
   前缀记录时，必须 `click_by_exact` / `ref_by_exact`，防止子串匹配错点
5. **轮询代替固定等待**：页面渲染、URL 跳转、异步结果一律 `wait_for_*`
   轮询（次数/间隔可传参）；`ab_wait` 仅作操作后短暂停顿
6. **软硬断言分级**：预期结果校验用软断言（WARN 累计，finish 汇总）；
   流程性关键节点（弹窗必须出现、必须进入目标页）用硬断言立即失败——
   错误状态下继续执行无意义
7. **文本进正则的风险**：将用户文本拼入 ERE 的路径（`extract_ref` 等）在
   文本含 `(` `[` `.` `*` `+` `?` 等元字符时会失配——优先走 JS 字面比较
   路径，或用 `case ... in *X*)` 字面匹配；正则模式必须由翻译者编写

## 三、用例解析规则

### 3.1 三段式结构

- `# 用例名称： XXX` → 脚本头注释业务链路概括
- `## 操作步骤` → 有序步骤列表，逐条翻译（§四）
- `## 预期结果` → 断言序列（§七）
- `## 前置条件` → 脚本头注释 + `require_vars` 校验 + 依赖脚本提示（§六），
  不翻译为动作（登录类前置由 `login` 幂等处理）

### 3.2 步骤文本规范化

- 原始步骤常有**编号错乱/重复/跳号**：翻译时忽略原始编号，按语义顺序
  重排，注释保留原步骤号便于回溯（`# step 4(原步骤 6): …`）
- **引用型步骤**（"重复步骤 N 操作，参数改为 ……"）：展开为完整动作序列；
  参数呈列表规律（多个条目 × 相同操作）时抽象为 `for` 循环遍历数据列表
  变量，注释注明"原用例为重复引用"
- **复合步骤**（一个步骤号下嵌多行子步骤，如信息录入块）：拆分为多个
  翻译单元，注释归属同一原步骤号

### 3.3 编号语义

文件名 `NNN_名称.md` 的 3 位编号承担**排序、依赖序、执行序**三重语义。
批量转换按编号升序；编排器按编号序串行。原始用例集缺漏编号时如数转换，
不代拟用例；平台侧需要补充的用例由用户增补 md 后再转换。

## 四、步骤 → 动作映射（通用动词识别表）

> 翻译每条步骤时按下表从上到下匹配**首个命中**的模式；未覆盖的动词按
> "最接近模式 + 语义决断"处理，决断理由写入脚本注释。

### 4.1 动词识别总表

| 步骤模式 | 典型写法 | 翻译模板 |
|---|---|---|
| 地址栏输入 URL / 访问 X | `浏览器地址栏输入：https://…` | `open_page`（open + 等待） |
| 完成系统登录（含账号密码） | `邮箱: "…" 密码: "…" 完成登录` | `login`（幂等，§4.2） |
| 点击【X】/ [X]按钮 / [X]链接 | `点击 [创建] 按钮` | `click_by_text 'X'`；前缀歧义用 `click_by_exact` |
| 点击 [X]，打开 [Y] 窗口 | `点击 [创建] 按钮, 打开 [创建] 窗口` | 点击 + `assert_visible 'Y'`（硬断言弹窗） |
| 点击 [X] Tab页签 | `点击 [组织] Tab页签` | `click_tab 'X'`（精确优先 + JS 点击） |
| [X] 信息录入（连续 `字段: "值"` 块） | `[新建Y] 信息录入` | 逐字段 `fill_by_label` / `fill_by_any_label`（§4.4） |
| 选择 [X]（下拉） | `类型： 选择 [Jenkins]` | `select_option '触发器' 'X'`；浮层不可点降级 `select_by_native`（§4.4） |
| 选择 [X]（单选/开关组） | `状态： 选择 [全量开放]` | `click_radio 'X'` 或 `ab_click 'X'` |
| 第 N 个下拉框选择 [X]（无标签） | `第一个下拉框选择 [Y]` | `refs_of_role combobox` 按位置取用（§4.4） |
| 节点/记录 X 右边的 …（行内操作） | `点击 X 右边的 ...` | `snapshot_line_after 'X' 'button'` + click |
| 树中点击节点 X | `组织树中点击节点 "X"` | `click_tree_node 'X'`（自动展开全树，§4.5） |
| 列表中搜索 "X" 关键字 | `列表中搜索 "X" 关键字` | `search_and_filter 'X'`；完成后 `clear_search_box`（§4.5） |
| 点击选择文件（OS 对话框） | `点击选择文件, 打开我的电脑…` | `upload_file`（§4.6），路径必须参数化 |
| 复制/记录生成的值 | `[复制] 生成的令牌` | 特征定位 + `save_element_value` 落盘（§4.7） |
| 引用其他用例产物 | `复制 [XX.md] 用例创建的 Y` | 从 `data/` 落盘文件读取，缺失报错提示先跑哪个脚本（§4.7） |
| 点击异步操作，返回结果 | `点击 [检测可用性] … 返回成功` | click + 轮询断言（§7.3） |
| 页面跳转到 X | `页面跳转到 Portal 首页` | `wait_for_url_match` / `wait_for_url_gone` + URL/快照断言 |
| 退出登录 / 确认退出 | `点击 [退出登录]，确认` | `click_user_info` → `click_by_exact '退出登录'` → `click_confirm_if_present`（§4.2） |
| 改用其他账号登录（用例内） | `改用 XX 登录` | 脚本内置身份切换（§4.2） |
| 列表/树"增加一条记录 X" | `列表中增加一条记录` | 不产生动作，并入预期结果断言（§七） |

### 4.2 登录、登出与身份切换（流程类模式）

- **登录**：统一 `login`（默认取 `ASDM_USER`/`ASDM_PASS` 凭据变量）——
  打开首页 → 轮询登录按钮 → 已登录且身份匹配则幂等跳过；身份不符自动
  退出当前账号再登录。业务脚本勿手写登录细节（登录用例本身除外，其
  冷启动兜底：首次点击可能丢失，按 `get url` 分派重试——已在登录页则
  延长等表单，仍停留首页则重新定位按钮重点）
- **身份切换**：单脚本单登录身份。脚本头部覆盖凭据变量（如
  `ASDM_USER="${<角色>_USER:-默认}"`），随后正常 `login`；调用方无需传
  环境变量
- **用户信息定位**：平台渲染用户名可能在字符间插空格（`abc01` →
  `a bc 01`）或渲染为"姓+名"显示名——快照子串匹配落空时自动退化 JS
  规范化空格匹配；特定身份检测须传 strict，防跨身份误判
- **登出**：`click_user_info` → 菜单若含"控制台管理"说明在管理后台，
  先回 Portal 再操作 → 退出登录 → `click_confirm_if_present`（二次确认
  有则点确定、无则跳过）→ 轮询等待退出完成。注意平台可能退到**未登录
  首页**（出现登录按钮）而非登录页——断言按实际行为写

### 4.3 点击与行内操作

- 常规点击一律 `click_by_text`（JS 优先 + 禁用轮询 + ref 兜底，§2.3）
- 前缀歧义（目标文本是其他元素的前缀）→ `click_by_exact`
- 记录/节点行内隐藏操作（"..."等）：`snapshot_line_after '特征文本' 'button'`
  取特征行之后第一个指定角色元素再 click
- **提交类按钮（创建/保存/上传）点击后无任何反应时，先怀疑表单必填项
  未满足（平台静默拦截：按钮不置灰、无提示、无请求）**，而非点击失效——
  排查并补全表单字段后再提交

### 4.4 表单、下拉与单选

- **表单填充**：`fill_by_label '标签' "值"`；同一字段在不同入口文案不同时
  `fill_by_any_label "值" '候选1' '候选2'` 依次尝试
- **下拉两步法**：`select_option '触发器标签' '选项文本'`——点触发器展开，
  从新快照点 option/listitem 选项；选项与触发器同名时从展开后的快照取
  新增 option 行，避免点回触发器
- **原生 select 兜底**：浮层下拉的 @ref 点击会报 CDP box model 错误
  （浮层元素不可点），改 `select_by_native "$ref" '选项'`
- **无标签下拉**（条件字段/无 aria-label）：`refs_of_role combobox` 枚举后
  按位置取用（`tail -2 | head -1` 等），或按弹窗区段标题截取快照
  （`sed -n '/区段标题/,$p'`）后取其中目标 combobox
- **选项文本带动态后缀**（如" (系统内置)"）：先从快照 `grep -oE` 提取
  完整选项文本，再按完整文本 select
- **角色核对陷阱**：步骤写"下拉框"的控件实际可能是**按钮**（如"未绑定
  组织"按钮点开搜索树）——翻译前先取快照核对控件真实角色，按真实角色
  选函数；误按 combobox 处理会导致值设到错误控件、提交按钮禁用、点击
  静默无效
- **单选/开关组**：`click_radio '选项'`（LabelText/radio 角色优先，退化
  可见文本）或 `ab_click '选项'`

### 4.5 树与搜索过滤

- **树操作**：树默认折叠、子节点未渲染。`click_tree_node '节点名'` 首次
  自动 `expand_all_tree`（JS 按 aria-label "Expand" 前缀点击全部折叠
  三角——展开后变 "Collapse"，天然只命中折叠节点），随后轮询精确匹配
  点击；同名前缀节点残留时精确匹配优先
- **创建后断言树节点**：提交点击 → 等待 → `reload` → 再 `expand_all_tree`
  + `wait_for_text` + 断言（列表刷新时序不可靠，重载兜底）
- **列表搜索**：`search_and_filter '关键字'`——点搜索按钮 → 轮询搜索框 →
  fill → `press Enter` → 轮询快照出现含关键字的结果行（**不可用"出现
  某按钮"判定过滤完成**——未过滤列表本来就有该按钮，会假完成导致在
  重渲染过渡态取值/点击）；处理完 `clear_search_box` 防残留污染后续定位
- **行内取列**：`cell_after '特征文本' N` 取特征 cell 之后第 N 个 cell
  文本（状态/类型列复核）

### 4.6 文件上传与确认弹窗链

OS 原生文件对话框不可回放，统一 `upload_file '定位文本' "$UPLOAD_FILE"`：

1. 函数先 JS 探测 `input[type=file]`（自定义上传区域背后挂隐藏 input，
   快照定位不到且误匹配报 CDP 错误），命中直接对选择器 upload；
2. 无隐藏 input 再按可见文本/ref 定位上传控件；
3. **确认弹窗链**（依序 soft 点击，未出现则跳过，保证幂等重跑）：上传
   校准确认、版本/重复覆盖确认等，按平台实际弹窗序列逐个
   `click_by_exact '按钮文本' ... soft || true`，覆盖确认后表单才展开
   完整字段；
4. 上传后的名称/描述"获取上传文件名称"类歧义：决断为取
   `basename "$UPLOAD_FILE"`，注释注明；
5. 用例中的 OS 路径（Windows 盘符等）在回放环境不可用，必须参数化为
   `UPLOAD_FILE` 并校验文件存在（`[ -f "$UPLOAD_FILE" ]`）。

### 4.7 数据抓取与跨用例传递

- **生成方落盘**：按产物特征定位（如令牌的特定前缀）取 ref →
  `save_element_value "$ref" "$DATA_DIR/<产物>.txt"`（value 为空自动退化
  get text；写入后 chmod 600）
- **消费方读取**：`VAR="${VAR:-$(cat "$DATA_DIR/<产物>.txt" 2>/dev/null)}"`，
  为空则报错并提示"先执行 replay_testcase/XXX_YYY.sh 或传入 VAR=..."
- 平台侧持久产物（组织/用户/项目等）不落盘，经 test-data.sh 的**同名
  变量对齐链**传递（§5.2）

### 4.8 iframe 内元素

快照 ref 范式覆盖不到的 iframe 元素用 `act_in_frame '选择器' 动作 '值'`：
BFS 遍历同源 frame 按选择器反查，要求全局唯一命中（多处命中返回 AMBIG
拒绝执行，防结构变化后静默错点）；fill/select 赋值后派发 input+change
（bubbles）兼容事件委托；NOEL/NOFRAME 时序性失败按 `ACT_RETRY` 重试。
选择器为 CSS 或 `xpath/` 前缀；仅同源 frame 可穿透。

## 五、数据机制：统一 test-data.sh

全部用例共用 `data/test-data.sh`（`: "${VAR:=默认值}"` 形式，**已导出的
环境变量优先**）。新用例的数据需求以**分节追加**方式并入该文件，禁止
生成每用例独立数据文件。

### 5.1 变量命名约定

| 类别 | 命名 | 说明 |
|---|---|---|
| 公共配置 | `BASE_URL` / `HEADED` | 平台地址；1=有头 0=无头 |
| 登录凭据 | `<角色>_USER` / `<角色>_PASS`（如 `ASDM_USER`/`ASDM_PASS`） | 每个登录身份一对；脚本按 §4.2 切换 |
| 名称类业务数据 | `<实体>_NAME`（组织/子组织/项目/配置名等） | 带时间戳后缀防重名（§5.2） |
| 关系引用类 | 下游引用变量与上游产物变量**字面一致** | 依赖链对齐（§5.2） |
| 选项/枚举类 | 直接存选项文本 | 下拉/单选的目标值 |
| 列表类 | 空格分隔的多值（如多个开关项） | 脚本内 `for x in $VAR` 遍历 |
| 外部凭据类 | 如 CI 凭证、代码托管 Token | 占位符值 + 编排豁免机制（§九） |
| 文件路径类 | 如 `UPLOAD_FILE` | 绝对路径；用例内 OS 路径不可用必须覆盖 |
| 运行产物类 | 不入 test-data.sh | 走 `data/` 落盘文件（§4.7） |

`require_vars` 只校验本用例实际用到的变量（按需裁剪，照搬全集会误伤）。

### 5.2 批次与依赖链对齐

- **名称类数据带时间戳后缀**（`TEST_TS`=MMDDHHmmss，如
  `<前缀><TEST_TS>`）：每批回放在平台生成全新数据、互不冲突——创建类
  用例不幂等，靠新批次规避重名
- **同批次字面对齐**：下游引用变量的值与上游产物变量**字面一致**（写
  静态值，不用变量引用），任何一环时间戳不一致，下游用例都会因找不到
  上游数据而失败
- 刷新数据执行 `generate-test-data.md`（唯一生成逻辑来源；test-data.sh
  仅静态快照，禁止写运行时生成逻辑）；回放前若同批数据已在平台创建过，
  先刷新再跑

### 5.3 敏感数据规则

- 回放脚本内**不出现明文密码/Token**，一律经 test-data.sh 或环境变量；
  用例 md 中的真实凭据抄录入 test-data.sh 对应变量
- 落盘凭据文件 chmod 600；test-data.sh 与 `result/` 禁止提交版本库
  （建议加入 .gitignore）
- 占位符凭据（如 `xxx…` 占位 Token）不阻断转换，由编排器豁免机制处理（§九）

## 六、前置条件、依赖链与幂等

- 前置条件翻译为：脚本头注释（逐条）+ `require_vars`（数据类）+ 必要的
  运行时守卫。守卫用于可前置检测的硬约束（如字段长度上限——超限会被
  输入框静默截断，带病执行必失败，应前置报错）；状态类前置默认假设
  满足，注释注明依赖的前置脚本编号
- **编号序即依赖序**：数据类依赖（上游产物/落盘文件）与状态类依赖
  （登录态、开关状态、功能入口可见性）都应通过编号排列体现；转换时
  从用例"前置条件"提取依赖并在 test-plan 依赖树中登记
- **幂等策略**（按用例类型选择并在脚本注释注明）：
  - 登录/导航类：天然幂等（已登录跳过 / 重复执行收敛）
  - 配置变更类（开关/状态修改）：重复执行收敛到目标状态，幂等
  - 上传/更新类：经"确认覆盖"弹窗链实现幂等重跑
  - 创建类（新建实体）：**不幂等**，重名必失败——依赖时间戳新批次数据
    （§5.2）或断点续跑（§九），禁止整批无脑重跑

## 七、预期结果 → 断言翻译

### 7.1 断言类型映射

| 预期结果模式 | 翻译模板 |
|---|---|
| 页面跳转到 X | `wait_for_url_match '特征段'` / `wait_for_url_gone '登录段'` + `assert_url_matches`；URL 无固定特征段时辅以快照特征文本断言（`assert_snapshot_contains 'X 页面特有文本'`） |
| 列表增加记录 X | 轮询等待 `cell "X"` 出现 + `assert_snapshot_contains 'X'`；**必须匹配列表行**（弹窗内输入框的 value 含 X 会误判通过）；列表条目多时先 `search_and_filter 'X'` 过滤再断言 |
| 树增加节点 X | `expand_all_tree` + `wait_for_text 'X'` + `assert_snapshot_contains 'X'` |
| 状态变为 X | `cell_after '名称' N` 取状态列 → `case` 断言含目标状态；批量修改后二次循环复核 |
| 值/令牌生成成功 | `assert_file_not_empty "$DATA_DIR/<产物>.txt"`（生成方已落盘） |
| 异步操作返回成功 | 轮询断言（§7.3） |
| 登录态出现/消失 | `is_logged_in` 正向校验；反向断言【登录】按钮重新出现 + 用户信息特征文本消失（`assert_snapshot_missing`） |
| 弹窗/窗口出现 | `assert_visible '窗口名'`（硬断言，流程关键节点） |
| 弹窗关闭 | 轮询等待弹窗特征文本消失（如输入框标签），超时 WARN |

### 7.2 软硬断言纪律

- **软断言**（assert_snapshot_* / assert_url_* / assert_file_not_empty）：
  失败 WARN+1 不中断，finish 汇总——用于预期结果校验，尽量跑完再汇总
- **硬断言**（assert_visible / 页面跳转校验 / 定位与数据抓取失败）：
  流程性关键节点立即 exit 1——弹窗未出现、未进入目标页、元素找不到、
  数据抓不到时，后续步骤已无意义
- 断言中的文本匹配用 `case ... in *X*)` 字面匹配（快照已存变量，无
  pipefail/SIGPIPE 问题）；正则元字符敏感场景用 `grep -qF`

### 7.3 异步操作轮询断言

点击异步触发器后轮询快照，成功/失败特征任一命中即止，超时按失败计
（特征词由翻译者按平台实际文案编写固定模式，不来自用例原文，无注入风险）：

```bash
ok=""
for ((i = 0; i < 30; i++)); do
    snap=$(snap_i)
    case "$snap" in
        *'成功特征'*|*'可用'*) ok=1; break;;
        *'失败特征'*|*'不可用'*) break;;
    esac
    sleep 1
done
[ -n "$ok" ] && echo "  [断言通过] <说明>" \
    || { echo "  [断言失败] <说明>" >&2; WARN=$((WARN+1)); }
```

## 八、平台行为特性清单（防静默失效，翻译/排障必读）

> 这些特性的共同特征：**平台不报错、不提示，操作静默无效**，表现为
> "点击没反应"或断言莫名失败。已沉淀为 common.sh 的内置对策；翻译新
> 用例遇到同类现象按此对照。

| # | 特性 | 内置对策 |
|---|---|---|
| 1 | 坐标点击对部分 SPA 链接/侧边栏元素静默失效 | ab_click JS 优先 + ref 兜底（§2.3-2） |
| 2 | 提交按钮因表单必填未满足而禁用/静默拦截（无提示无请求） | ab_click 禁用轮询；翻译时核对全部必填字段 |
| 3 | 输入值超字段长度上限被**静默截断**（填入值 ≠ 变量值，断言必失败） | 数据侧控制长度 + 脚本前置长度守卫（§六） |
| 4 | 用户名渲染插空格 / 渲染为"姓+名"显示名，快照子串匹配落空 | JS 规范化空格匹配 + 显示名候选 + strict 防跨身份误判（§4.2） |
| 5 | 浮层下拉 @ref 点击报 CDP box model 错误 | select_by_native 原生 select 兜底（§4.4） |
| 6 | 控件真实角色与步骤描述不符（写"下拉"实为按钮+搜索树） | 翻译前快照核对真实角色（§4.4 角色核对陷阱） |
| 7 | 树默认折叠、子节点未渲染；同名前缀节点残留 | expand_all_tree + 精确匹配优先（§4.5） |
| 8 | 搜索过滤完成判定不可用"某按钮出现"（未过滤本来就有） | 以含关键字结果行为完成特征（§4.5） |
| 9 | 重复上传触发"版本覆盖确认"弹窗，确认后表单才展开 | soft 确认弹窗链，幂等重跑（§4.6） |
| 10 | SPA 首帧未挂载事件，首次点击丢失 | 按 get url 分派重试（§4.2 登录冷启动） |
| 11 | 退出登录回到未登录首页而非登录页 | 断言按实际落点写（§4.2 登出） |
| 12 | 创建成功后弹窗不自动关闭 / 列表不即时刷新 | 轮询列表行出现 + 主动关窗 + reload 兜底（§4.5/§7.1） |

## 九、全量回归编排（task/run-all.sh + test-plan.md）

批量转换（§十）或首次建立回放体系时生成：

1. **`task/test-plan.md`**：按 `.asdm/toolsets/ui-auto-testing/actions/generate-test-plan.md`（§五 A 模板）生成
   静态实例——任务清单（编号/名称/执行入口/登录身份/前置/数据依赖/
   产出/状态）、依赖树、执行方式、通过标准、豁免与阻塞记录表、
   脚本 vs 用例原文差异备注、执行记录表（执行时填写）
2. **`task/run-all.sh`** 编排器要点：
   - **运行环境守卫**：依赖 bash 专属特性（进程替换/数组），被 sh/dash/zsh
     调用时自动 `exec bash` 重执行自身
   - **编号序串行**执行全部任务；单任务失败**不中断**，继续剩余任务
     （下游依赖可能连锁失败，属预期留痕）；失败后补跑用**断点续跑**
     （从失败任务起单任务执行），禁止整批重跑（创建类不幂等）
   - **豁免判定**：外部依赖不满足（上传文件不存在、Token 为占位符等，
     按 §5.1"外部凭据类/文件路径类"变量）的任务自动跳过并记"豁免"，
     条件满足即自动执行（环境变量传入真实值解除）
   - **日志落盘**：每任务 `result/<NNN>_<名称>-<时间戳>.log`（现役实现为
     固定名覆盖式 `result/<NNN>_<名称>.log`，见 test-plan.md §七 差异 14）
     （tee 同步控制台）；整轮输出 + 汇总表 + 统计落综合日志
     `result/run-all-<时间戳>.log`
   - **身份切换零感知**：需切换身份的脚本内置凭据覆盖（§4.2），编排器
     无需传环境变量
   - 退出码：存在失败任务 → 1（CI 判定）
   - 布局适配：脚本位于 `replay_testcase/` 子目录，以
     `${ROOT_DIR}/replay_testcase/${tc}.sh` 定位入口（`tc` = `<NNN>_<名称>`，
     无 `replay_testcase_` 前缀）；目录布局变更时同步调整

## 十、执行流程（AI 操作步骤）

### 10.1 输入解析

用户指定的输入缺省为 `test-cases/`，按形态分派：

| 输入形态 | 判定条件 | 处理方式 |
|---|---|---|
| 单文件 | 路径存在且以 `.md` 结尾 | 仅转换该文件（§10.2） |
| 目录 | 路径是目录 | 扫描并批量转换（§10.3） |
| 无效 | 不存在 / 非 md / 非目录 | 报错终止并说明原因，不做猜测 |

单文件同样须符合 `NNN_名称.md` 命名（3 位数字编号）；不符合时报错说明
命名要求，不代拟编号。目录扫描不递归子目录。

### 10.2 单用例转换流程

1. 读取用例 md，按 §三 解析三段式；编号错乱/重复引用按 §3.2 规范化
2. 确认输出环境：`common/common.sh` 存在则复用；不存在先按 §二 建立公共库与
   `replay_testcase/`、`data/`、`task/`、`result/` 目录骨架及 `data/test-data.sh`
3. 从文件名提取 `<NNN>_<名称>`，按 §2.1 骨架生成
   `replay_testcase/<NNN>_<名称>.sh`（require_vars 按需裁剪）
4. 本用例新数据变量按 §5.1 命名约定**分节追加**进 test-data.sh
   （已存在同名变量不覆盖；test-data.sh 被人工编辑过时仅追加，整体
   重生成须走 generate-test-data.md）
5. 按 §四 逐条翻译操作步骤；按 §七 翻译预期结果为断言序列；翻译中的
   语义决断（歧义步骤的取舍）写入注释
6. 验证：`bash -n` 语法检查 → 平台可达性检查（`curl -sI "$BASE_URL"`）→
   实跑（工作目录 = `replay-testcase/`，不设环境变量，验证 test-data.sh 与
   common.sh 的 `../` 相对定位链路）；元素定位失败时
   `agent-browser snapshot -i` 人工比对可见文本，修正匹配关键字；
   同现象复现 ≥2 次的定位/操作模式按 §2.2 沉淀进 common.sh
7. 交付说明：运行方式（有头/无头/覆盖变量）、依赖的前置脚本、新增
   变量清单、翻译决断点

### 10.3 目录批量转换

1. 列出目录下全部 `*.md`，按文件名升序
2. 逐个过滤（不满足任一条则跳过，原因记入汇总）：
   - 文件名形如 `NNN_名称.md`
   - 内容含 `## 操作步骤` 节（三段式最小校验）
   - README/模板等不符合命名的文件天然排除
3. 每个通过过滤的用例**独立执行 §10.2 全流程**；单个失败记录后继续
   下一个，不中断批次
4. 批量验证分级：`bash -n` 全量；实跑按编号序串行（依赖序即编号序），
   用例较多时与用户约定抽样子集（至少覆盖登录用例与一个含外部依赖的用例）
5. 全量转换时按 §九 生成/刷新 `task/run-all.sh` 与 `task/test-plan.md`
6. 交付汇总清单（表格）：编号 / 名称 / 脚本路径 / 新增变量 / `bash -n`
   结果 / 实跑结果 / 跳过或失败原因；目录为空或全被过滤时明确提示，
   不产出任何脚本

## 已知限制

- 定位依赖**界面可见文本**：平台文案改版会导致文本匹配失配，需同步更新
  脚本关键字与 test-data.sh 选项值；纯图标无文本按钮需补角色/aria-label
  匹配模式
- common.sh 的快照定位假设元素行格式形如 `- role "名称" [ref=eN]`；
  agent-browser 大版本变更快照格式时需同步调整定位函数（可先
  `agent-browser skills get core --full` 核对 ref 约定）
- 同文本歧义（触发器与下拉选项同名、多条同名记录）按"首个精确命中"
  处理，复杂歧义需人工指定或改用 iframe/JS 定位（§4.8）
- 用例的自然语言歧义需翻译时人工决断，决断点必须写入脚本注释
